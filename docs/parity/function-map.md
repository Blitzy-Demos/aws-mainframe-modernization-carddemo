# CardDemo function map

Pattern-lane map (AAP 0.9.1) of every key, selector and menu option that the 21 BMS maps of the carried online programs offer: the COBOL paragraph that handles it, the web control that replaces it, and the API request that control sends. Every ENTER and PF-key path a carried map offers is listed (legacy disposition, AAP 0.6.5); 3270 mechanics become UI controls, not endpoints (AAP 0.5.4.4); a key with no obvious control is escalated. It gates `web/src/pages/**`, `web/src/nav/menu.ts`, `web/e2e/navigation.spec.ts` and `web/e2e/forms.spec.ts`; `web/e2e/navigation.spec.ts` fails on an F-ID it does not cite and on a cited F-ID this file does not define.

Business rules, messages and statuses are not restated here: they are the P-rows of `docs/parity/parity-oracle-audit.md` and the V-rows of `docs/parity/validation-audit.md`, cited by ID. Escalations raised here are consolidated into `docs/parity/escalations.md`.

Author: `blitzy-audit-author`. Reviewer of every row: `blitzy-cobol-reviewer`.

## Conventions

- Tables are GitHub pipe tables, one record per line; a literal `|` inside a cell is written `\|`. One table per map, header `| ID | BMS map | Key or field | COBOL action | UI control | Endpoint |`.
- **ID** `F-<MAP>-<nnn>`, `<MAP>` being the BMS map cell (the mapset name), numbered per map from 001.
- Citations are `[<path>:L<n>]` or `[<path>:L<n>-<m>]`, with repository paths in their stored case and 1-based physical line numbers.
- **Key or field** starts with the key: `ENTER`, `PF2` … `PF12`, `selector S`, `selector U`, `selector D`, `option <n>` or `other AID keys`. The citations after it are the BMS line that offers the key (the key legend) and, where the key acts on an input, that input field; a key absent from the legend cites the legend line and says so. A key the program handles in more than one state has one row per state, the state being named in **COBOL action**.
- **COBOL action** is the paragraph and its effect, then the program lines; P-IDs name the parity-audit rows that record the rule. A decision that departs from the COBOL names its escalation.
- **UI control** is `route=<path>; control=<role> "<accessible name>"`, followed where needed by `input=<kind> "<label>"` (kind `textbox`, `password` or `radio`; one pair per input the control needs, in screen order; the input is located by its label) and `target=<path>` (the route the control navigates to).
  - Roles: `link`, `button`, `menuitem`, `form-submit` (the submit button of the form, ARIA role button; Enter in a field of the form activates it), `dialog-action` (a button of the open confirm dialog, `web/src/components/confirm-dialog.tsx`), `breadcrumb`.
  - `route` is the route that renders the control. For `option <n>` rows it is the destination of the menu link, which the sidebar renders on every authenticated route (CM00 group "Card management", CA00 group "Administration"), the dashboard `/` and the admin landing `/admin` render as their menu lists, and `web/src/nav/menu.ts` takes as the entry's route.
  - `:accountId`, `:cardNumber`, `:tranId`, `:authId`, `:userId` and `:code` are the route parameters of AAP 0.5.4.1.
  - `—` means no control; the row's escalation says why.
  - Accessible names are exact and case-sensitive. Row actions (`selector` rows) render in each row of the data table as `Button variant="link"`; `Previous` and `Next` are the data table's `PaginationPrevious` and `PaginationNext`.
  - PF3 Back links target the parent route in the URL hierarchy; a top-level route returns to `/` for user functions and `/admin` for admin functions. PF3 sign-off on COSGN00, COMEN01 and COADM01 is the `menuitem` of the app-shell user menu, whose trigger is named by the signed-on user ID.
  - In the confirm dialog `dialog-action "Confirm"` sends the request (with `confirm: "Y"` where the resource carries a confirmation) and `dialog-action "Cancel"` closes it without a request (the COBOL `N`).
- **Endpoint** is the API request that carries out the key's function: the resource of AAP 0.3.1 with the shared pagination query `start_key`, `direction` and `page_size` (AAP 0.6.4) and the query names of `docs/parity/validation-audit.md`. A control that only opens the confirm dialog has `—`, its `dialog-action "Confirm"` row carrying the request; a link that only moves has `— (navigation)`; `—` otherwise means no request.
