# CardDemo escalation log

This log is the single register of the exceptions met while replacing the CardDemo COBOL oracle: every anomaly found in pattern-lane work (#1), which moves that item to the derive lane (#2) instead of being pattern-matched through; every defect-like COBOL behaviour the replacement reproduces; every mismatch between the request and the repository; and every case whose equivalence cannot be proven.

Every E-ID cited in `docs/parity/parity-oracle-audit.md`, `docs/parity/validation-audit.md` and `docs/parity/function-map.md`, each `no-message (E-nn)` message cell included, resolves to a row of the table below. E-01 to E-22 are the seeded log. E-65 and E-66 are raised by the generation of the `web/src/components/ui` files with shadcn CLI 4.23.0 and logged here directly, not copied from those three files. E-77 is raised by the port of the CBTRN02C posting rules to `crates/domain/src/rules/posting.rs` and is likewise logged here directly. E-79 is raised by the codec's ASCII/EBCDIC cross-check and is likewise logged here directly. E-84 and E-85 are raised by the npm advisory audit of `web/pnpm-lock.yaml` (`pnpm --dir web audit`) and are likewise logged here directly. E-86 is raised by the code review of the CTLI first-page re-read in `crates/domain/src/rules/tran_type_list.rs` and is likewise logged here directly. Every other row from E-23 on is a row one of them raises in its own `Escalations raised` table, copied here verbatim. A new finding takes the next free number after the highest ID in the table and is appended at its end; IDs are never renumbered or reused.

Status, the first word of the Status cell, optionally followed by `: <note>`:

- `resolved`: the repository or a request clause decides the item.
- `open`: the item needs the user's decision. It blocks sign-off in `docs/parity/signoff.md`, not code.
- `halt`: equivalence cannot be proven. No code that guesses the result is written, the input class and its COBOL path are listed in `docs/parity/signoff.md`, and work whose results do not depend on the case continues.

Conventions:

- One GitHub pipe table, one record per line; a literal `|` inside a cell is written `\|`.
- IDs are `E-<nn>` with two or more digits, unique and ascending.
- Repository evidence is cited as `[<path>:L<n>]`, `[<path>:L<n>-<m>]` or `[<path>]` (a file or directory), with paths in their stored case and 1-based physical line numbers. Files written by this work, such as `deny.toml`, are cited by path only. Counts, registry versions, advisories and IBM manuals are plain text.
- Row IDs in parentheses (`P-`, `V-`, `F-`) name the audit rows that record the item.
