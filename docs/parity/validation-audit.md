# Input-validation audit

Derive-lane audit of every input edit, record-state outcome and I/O failure message of the 19 CardDemo online programs that carry an input edit (AAP 0.9.1). It is the single source for each COBOL validation message, the HTTP status it maps to, the BMS field it marks and the order in which the COBOL reaches it. It gates the validation functions in `crates/domain/src/rules/**`, the message constants in `crates/domain/src/messages.rs`, the request DTO field enums and constraints in `crates/api/src/dto/**`, the zod schemas and `bmsFieldMap` in `web/src/schemas/**`, and the error tests in `crates/api/tests/*`. `crates/api/tests/validation_audit_coverage.rs` fails when a V-ID is cited by no test. Record layouts, business rules, fixture expectations and anomalies are in `docs/parity/parity-oracle-audit.md`, whose P-IDs and E-IDs the rows cite.

## Conventions

- One table per program, header `| ID | Program | Validation paragraph | Trigger condition | Message text | Status | BMS field | Order |`, one record per line. A `|` inside a cell is written `\|`.
- **ID** `V-<PROGRAM>-<nnn>`, numbered per program from 001. Rows of a copybook procedure (CSUTLDPY, CSLKPCDY) and of a linked program (COPAUS2C) carry the calling program's ID and cite the copybook or program lines.
- **Validation paragraph** names the REST operation where a program serves more than one, then the COBOL paragraph, then citations `[<path>:L<n>]` or `[<path>:L<n>-<m>]` of 1-based physical lines.
- **Trigger condition** is the condition in plain terms, then `; example=<value>` (a failing input from the seeded fixture state, citing the parity audit row that pins the fixture value, or `no fixture input` for an I/O failure) and `; kind=<kind>`. The kind is the `DomainError` kind (AAP 0.6.4: `Invalid`, `Empty`, `NotFound`, `Duplicate`, `Conflict`, `SignonFailed`, `Unexpected`), or `none` for a message-only outcome that is not an error and writes nothing.
- **Message text** is a code span holding a double-quoted string, byte-identical to the COBOL literal between its quotes, with no padding to the receiving field. Inside the string, `\"` stands for a double quote and `\\` for a backslash. For an 88-level or an `X(n)` constant the VALUE literal is taken. A STRING-built text shows each variable part as `{<COBOL-FIELD>}`, and the note after the code span names the delimiters, the receiving field and its width. A path that sets no message is `no-message (E-nn)`, linking the escalation that decides its status.
- **Status** is the HTTP status of the response; the response body carries the message text as `message` (AAP 0.6.4).
- **BMS field** is the field the COBOL marks with `MOVE -1 TO <field>L`, written without its `L/F/A/I/O/C/H` suffix as in the symbolic map copybook, or `—` when no single field is marked. It is the `fields[].field` value of the error response.
- **Order** is the rank at which the COBOL reaches the rejection for one input, 1 being checked first; alternative outcomes of one test share a rank: the branches of one EVALUATE or the responses of one I/O. Where more than one branch condition of a shared rank holds for an input, the branch listed first (the lower ID) is taken, as COBOL takes the first true WHEN, so (Order, ID) orders the rows completely. Order restarts for each REST operation of a program. Which row supplies `message` when several fire is stated per program under **Precedence**.

## Status mapping

| Kind | Status | Rows |
|---|---|---|
| `Invalid`, `Empty` | 400 | Input edits. A row is 400 when the path sets the program's error flag (WS-ERR-FLG, INPUT-ERROR) or the program ends the task at the first failing edit, the CT02 blank or N confirmation included (it sets WS-ERR-FLG [app/cbl/COTRN02C.cbl:L169-181]) |
| `NotFound` | 404 | A key that addresses no record, whatever flag the COBOL sets (E-50) |
| `Duplicate`, `Conflict` | 409 | A duplicate key on add, a record changed since it was read, a delete blocked by child rows |
| `SignonFailed` | 401 | COSGN00C user not found and wrong password |
| `Unexpected` | 500 | Any other I/O failure, with the COBOL message the program shows for it; lock failures included (E-50) |
| `none` | 200 | The path only sets a message: no error flag, no write (for example `"Confirm to make a bill payment..."`, `"No change detected with respect to values fetched."`, page-boundary texts, E-54) |

A path with no message takes its status from this table through E-24 or E-49. A message that the COBOL replaces later in the same task is recorded at the row whose text the response carries, and the replaced text is named in the note.

## COACTUPC

Operation: `PUT /accounts/{id}`. One request performs the ENTER fetch (1210-EDIT-ACCOUNT and 9000-READ-ACCT), the comparison and edits of 1200-EDIT-MAP-INPUTS, and the PF5 write 9600-WRITE-PROCESSING; the version token stands for ACUP-OLD-DETAILS (AAP 0.3.7).

Precedence: every edit runs, and each message is moved only while WS-RETURN-MSG is blank (WS-RETURN-MSG-OFF [app/cbl/COACTUPC.cbl:L479-480]), so the failing row with the lowest Order supplies `message`. Every failing edit sets its field flag; the cursor goes to the first flagged field in 3300-SETUP-SCREEN-ATTRS [app/cbl/COACTUPC.cbl:L3009-3167], and `fields` lists the flagged BMS fields in Order.

Inputs: 1100-RECEIVE-MAP turns a field holding `*` or spaces into LOW-VALUES [app/cbl/COACTUPC.cbl:L1040-1425]; an absent or blank JSON field is that LOW-VALUES input. Signed amounts that pass TEST-NUMVAL-C are converted there with NUMVAL-C (E-40).

STRING-built texts are DELIMITED BY SIZE into WS-RETURN-MSG PIC X(75) [app/cbl/COACTUPC.cbl:L479]; bytes past 75 are cut. `{WS-EDIT-VARIABLE-NAME}` is FUNCTION TRIM of WS-EDIT-VARIABLE-NAME PIC X(25) [app/cbl/COACTUPC.cbl:L53], holding the name the row gives; a longer name is cut to 25 bytes first (E-45).

Examples change one field of the GET body of account 00000000001 (P-CVACT01Y-015; customer 000000001, P-CVCUS01Y-021).

## COCRDUPC

Operation: `PUT /cards/{id}`, the path carrying CC-CARD-NUM and the body the account number, the card fields and the version token, which stands for CCUP-OLD-DETAILS (AAP 0.3.7). One request performs the key edits and 9100 fetch, the comparison and edits of 1200-EDIT-MAP-INPUTS, and the PF5 write 9200-WRITE-PROCESSING.

Precedence: each edit runs, and a message is moved only while WS-RETURN-MSG is blank (WS-RETURN-MSG-OFF [app/cbl/COCRDUPC.cbl:L173-174]), so the failing row with the lowest Order supplies `message`. Two texts are set unconditionally and win whatever their Order: NO-SEARCH-CRITERIA-RECEIVED when both keys are blank [app/cbl/COCRDUPC.cbl:L656-659], and the write outcomes after 9200. The cursor goes to the first flagged field in 3300-SETUP-SCREEN-ATTRS [app/cbl/COCRDUPC.cbl:L1211-1235].

## COACTVWC
