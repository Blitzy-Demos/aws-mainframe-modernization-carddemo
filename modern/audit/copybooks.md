# Copybook field audit

This is the derive-lane (#2) audit of the record layouts the replacement ports. For every field of the 17 copybooks below it records the byte offset and length, the Rust type that holds the value and the PostgreSQL column that stores it. It comes before any record struct, codec, migration or row type, and code that consumes it is accepted only once the reviewer marks this file `Accepted` in the status table of `README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16).

- Timestamp writers and the CP00 field flow: `app/cbl/{CBTRN02C,CBACT04C,COTRN02C,COBIL00C}.cbl` and `app/app-authorization-ims-db2-mq/cbl/COPAUA0C.cbl`.

## How the rows are proved

- i8 (codec A): `modern/crates/domain/tests/codec_a_roundtrip.rs` and `modern/crates/copybook/tests/pic_roundtrip.rs`.
- d9 (codec B): `modern/crates/persistence/tests/schema.rs` and `modern/crates/persistence/tests/codec_b_roundtrip.rs`.
- The typed-error class rows are also the conditions `modern/crates/copybook/tests/total_parsers.rs` and `modern/crates/domain/tests/total_parsers.rs` exercise (Total Parsers Over Untrusted Input).

Each test that proves a row carries `// audit: <Rule ID>`. A row whose field has no column is proved by codec A alone. This file has no `Layer` column: none of its rows is observable through an endpoint or a screen.

## Reading the table

- Rule ID: `<COPYBOOK>-<nnn>`, numbered from 001 in field order, then any column that is not a copybook field; `PIC-<nnn>` for a codec rule that holds for a whole class of fields.
- Program: the copybook, then the in-scope programs that `COPY` it (AAP 0.5.5). A class row lists the copybooks it applies to.
- Paragraph: the 01 record or the group that contains the field. A copybook without its own 01 level takes the 01 its copying programs declare.
- Copybook field or PIC: the declaration as written, COBOL spellings included.
- Input condition: the 0-based byte offset and the length within the record; for a class row, the bytes it decodes.
- Expected result: the Rust type, the column (`table.column` and its SQL type), keys, and the redaction of sensitive fields.

Rust types: `PicX<N>`, `PicU<N>` (`u64`), `PicS<N>` (`i64`), `PicDate` and `PicTimestamp` from `copybook::pic`; `Money<N>` (scale 2), `Rate<N>` (scale 2) and `MoneyExpr` from `domain::money`; `Count` (`i16`); `CardNumber`, `Ssn`, `Cvv` and `Password` from `domain::sensitive`.

## Column names

- Key, join and index columns take the shared names AAP 0.3.3.4 gives them: `acct_id`, `card_num`, `cust_id`, `group_id`, `tran_type_cd`, `tran_cat_cd`, `tran_type` (the VSAM type key), `tran_id`, `usr_id`, `auth_date_9c`, `auth_time_9c`, and `proc_ts` with its pair `orig_ts`. A timestamp's layout code is `<col>_form`.
- Every other column is the field name in lower case with hyphens as underscores and the COBOL spelling kept (`acct_expiraion_date`, `merchant_catagory_code`), so each column traces back to its field by name. The record prefix stays (`acct_`, `card_`, `cust_`, `tran_`, `dis_`, `err_`), except `SEC-` and `PA-`, which the AAP drops (`usr_type`, `approved_auth_amt`).
- `FILLER`, and the named filler `SEC-USR-FILLER`, become `filler`.
- `users.password_hash` replaces `SEC-USR-PWD`. Three columns are not copybook fields and have rows of their own: `cards.card_ref`, `pending_auth_details.acct_id` (the IMS parent key) and `cssl_error_log.id`.

## Rules governing this file

- Typed Dates and Timestamps: the five `X(10)` dates map to `PicDate` and `DATE`; the two `X(26)` timestamps of `CVTRA05Y` and their `CVTRA06Y` twins map to `PicTimestamp` and `TIMESTAMP(6)` plus a layout code (E33). The byte codec is outside the rule, so the class rows state the text layouts. Other date-like fields (`X(04)`, `X(06)`, `X(08)`) stay text, and their rows say so.
- Checked Integer Narrowing: every `9(n)` and `S9(n)` integral field (`PicU`, `PicS`) is 64-bit (`u64` or `i64`, `BIGINT` with a literal range check), so identifiers of 10 or more digits are 64-bit end to end (PIC-003, PIC-023). The two binary `S9(4) COMP` counts are the exception: `Count` (`i16`) in a `SMALLINT` column, which holds every halfword, so nothing narrows (PIC-011, CIPAUSMY-009, CIPAUSMY-010).
- Cardholder Data Redaction: every sensitive field names its type and redacted form (PIC-024). This file quotes no fixture card number or SSN.
- Total Parsers Over Untrusted Input: the typed-error class rows are the conditions every public decoder returns as an error, never a panic.
- R7 — Anomaly handling: anomalies are cited by their escalation ID or proposed below as `X-COPYBOOKS-<n>`, never normalised. R16: `app/**` is read only.

- `X-COPYBOOKS-1`
  - Found in: `app/jcl/DUSRSECJ.jcl:35-44,48,66`; `app/cpy/CSUSR01Y.cpy:17-23`.
  - Anomaly class: fixture-shape.
  - Finding: the 10 in-stream USRSEC records are stored as 57-byte lines. The trailing blanks of the 80-column card images, which include all 23 bytes of `SEC-USR-FILLER` (offset 57), are not kept in the file, against the 80-byte `CSUSR01Y` record (`LRECL=80`, `RECORDSIZE(80,80)`).
