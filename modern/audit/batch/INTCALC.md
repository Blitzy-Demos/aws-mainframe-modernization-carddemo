# INTCALC audit: CBACT04C, the monthly interest calculator

This is the derive-lane (#2) audit of the batch job INTCALC and its program CBACT04C, which the replacement runs as `carddemo-batch intcalc`. It comes before `modern/crates/domain/src/batch/cbact04c.rs`, `modern/crates/batch/src/jobs/intcalc.rs` and `modern/crates/batch/tests/intcalc.rs`, and code that consumes it is accepted only once the reviewer marks this file `Accepted` in the status table of `../README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16). Audited defects are expected results. Where the AAP's prose or the plan's description of this job differs from the code, the code is authoritative and the difference is proposed below as an escalation candidate.

## The job

- JCL: `STEP15` runs `CBACT04C` with `PARM='2022071800'` (`INTCALC.jcl:22`). Its DDs are `TCATBALF` (category balances, KSDS), `XREFFILE` (cross-references, KSDS) with `XREFFIL1`, the path over the alternate index on `XREF-ACCT-ID`, `ACCTFILE` (accounts, KSDS, opened for update), `DISCGRP` (disclosure groups, KSDS) and `TRANSACT`, the new generation `AWS.M2.CARDDEMO.SYSTRAN(+1)` with `DISP=(NEW,CATLG,DELETE)` and `DCB=(RECFM=F,LRECL=350,BLKSIZE=0)` (`INTCALC.jcl:27-41`).
- Replacement: subcommand `intcalc` of `carddemo-batch`, with option `--parm-date` (default `2022071800`, the JCL's PARM; CBACT04C-001). It reads `tran_cat_balances`, `accounts`, `card_xref` and `disclosure_groups`, updates `accounts` (CBACT04C-026) and writes one file, `SYSTRAN.G<nnnn>` in `var/systran` under `CARDDEMO_VAR_DIR` (`runtime::config::Config::systran_dir`), named by `runtime::gdg::next_generation` (CBACT04C-024). The file is local output and never leaves the host (Local-Only Runtime).
- The SYSTRAN records are written to the file only. They are not inserted into `transactions`: merging them into the transaction file is COMBTRAN's work, and COMBTRAN is out of scope (AAP 0.2.3; CBACT04C-029).
- Today: the injected `Clock` stands in for `FUNCTION CURRENT-DATE` and is read once per SYSTRAN record (CBACT04C-022); tests use `FixedClock` and compare time fields by format.
- SYSOUT: each `DISPLAY` becomes one tracing event on standard output, in program order (X-INTCALC-4); standard output also carries the SYSTRAN path line (CBACT04C-024).

## Reading the table

- Rule ID: `CBACT04C-<nnn>`, in the order in which the program first reaches the rule; the failure rows follow the normal flow (CBACT04C-031 to CBACT04C-038).
- A displayed line is written as its literal in backticks, then `+` and the item displayed after it; `DISPLAY` writes its operands with nothing between them. A literal's length is given where it ends in a space.
- Displayed lines as events: each line becomes one tracing event whose message is the displayed text, in program order (X-INTCALC-4). - Replacement: where a row says how the replacement realises a COBOL effect (a table read or update, a file operation, an exit status), that sentence starts with "Replacement:".

## Rules governing this file

- Cardholder Data Redaction: each SYSTRAN record carries a full card number in `TRAN-CARD-NUM` (CBACT04C-021). The file is local batch output, like the statement and report files (AAP 0.3.4.4), not egress; no displayed line, tracing event, error or standard-output line of this job carries a card number, and this file names the field and quotes no value.
- Typed Dates and Timestamps: the two SYSTRAN timestamps are typed `PicTimestamp` values with layout `D` (PIC-019, E33; CBACT04C-022). `PARM-DATE` is not one of the copybook date fields the rule names (AAP 0.3.3.1): the program never reads it as a date, only as the first ten characters of `TRAN-ID`, so it stays text (CBACT04C-001, CBACT04C-015).
- Checked Integer Narrowing: the six-digit `TRAN-ID` suffix wraps after 999999 (CBACT04C-016); the replacement wraps it explicitly, with a `// TRUNCATION:` comment citing that row. The money stores cite their `ARITH-` rows.
- Total Parsers Over Untrusted Input: `--parm-date` is external input; CBACT04C-001 makes its parse total, with a typed error for every value it does not accept.
- Money constraint and R1: amounts appear only through ARITH-001 to ARITH-017; nothing here involves floating point.
- Behaviour constraint: E07 (CBACT04C-010), E08 (CBACT04C-027) and the mislabelled open text (CBACT04C-034, X-INTCALC-5) are expected results, reproduced and never fixed.
- R7 — Anomaly handling: anomalies are proposed below as `X-INTCALC-<n>` and `X-INTCALC-H<n>`, never normalised. R16: `app/**` is read only.

## Escalation candidates

Proposed under R7 — Anomaly handling. The reviewer folds each candidate into `ESCALATIONS.md` under the next free ID, as its `## Later entries` section describes; until then the rows above cite the candidate names.

- `X-INTCALC-1`
  - Found in: `CBACT04C.cbl:175-180,476-480`; `INTCALC.jcl:22`; the plan's description of this file, which asks for a `--parm-date` of exactly 10 characters.
  - Anomaly class: declaration-not-followed.
  - Finding: `EXTERNAL-PARMS` declares `PARM-LENGTH`, which the program never tests, and the program never validates `PARM-DATE`. A PARM of 10 characters is used as given, whatever the characters: `ABCDEFGHIJ` gives IDs that start `ABCDEFGHIJ`. A longer PARM contributes its first 10 characters and the rest is ignored. A shorter one, or none, leaves bytes of `PARM-DATE` beyond the PARM text, whose content no source fixes (X-INTCALC-H4). Accepting exactly 10 characters, as the plan describes, would reject longer values that the COBOL handles deterministically, a difference the Behaviour constraint does not allow.
  - Proposed resolution: the replacement accepts any value of at least 10 bytes, each printable ASCII, and uses its first 10; it rejects every other value with a typed error before it emits a line, reads a table or creates a file (CBACT04C-001). Printable ASCII is required because `TRAN-ID` is a `PicX<16>`, which holds only such bytes (PIC-001, PIC-002). The rejection of a shorter value is not claimed as parity. The reviewer confirms.
