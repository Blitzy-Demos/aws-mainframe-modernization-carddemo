# CBPAUP0J audit: CBPAUP0C, the expired pending-authorization purge

This is the derive-lane (#2) audit of the batch job CBPAUP0J and its program CBPAUP0C, which the replacement runs as `carddemo-batch cbpaup0j`. It comes before `modern/crates/domain/src/batch/cbpaup0c.rs`, `modern/crates/batch/src/jobs/cbpaup0j.rs` and `modern/crates/batch/tests/cbpaup0j.rs`, and code that consumes it is accepted only once the reviewer marks this file `Accepted` in the status table of `README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16). Where the AAP's prose and the code differ, the code is authoritative and the difference is proposed below as an escalation candidate.

## The job

- JCL: `STEP01` runs `DFSRRC00` with `PARM='BMP,CBPAUP0C,PSBPAUTB'`, so CBPAUP0C is an IMS batch message program under PSB `PSBPAUTB`. Its one database PCB, `PAUTBPCB` (the second PCB, after the I/O PCB that `CMPAT=YES` supplies; `PAUT-PCB-NUM` is `+2`), has `PROCOPT=AP` over the root `PAUTSUM0` and its child `PAUTDTL1` of the HIDAM database `DBPAUTP0` (`CBPAUP0C.cbl:82`; `PSBPAUTB.psb:17-20`; `DBPAUTP0.dbd:18,28-37`). SYSIN is one in-stream card, `00,00001,00001,Y` (`CBPAUP0J.jcl:24-25,36-37`).
- Replacement: subcommand `cbpaup0j` of `carddemo-batch`, with option `--sysin` (default `00,00001,00001,Y`, the card's text). It reads and deletes rows of `pending_auth_summaries` and `pending_auth_details` (migration `0004_authorizations.sql`, the root and child segments) and touches no other table and no file.
- Effects: qualifying details are deleted (CBPAUP0C-015), and a summary is deleted by the rule of CBPAUP0C-016, its remaining details with it through `ON DELETE CASCADE` (CIPAUDTY-029; AAP 0.3.3.4). No summary row is ever updated: CBPAUP0C issues no `REPL`, so its subtractions are discarded (CBPAUP0C-017). This contradicts the "summary adjustments" of AAP 0.3.4.3 (X-CBPAUP0J-1).
- Commits: one PostgreSQL transaction per checkpoint interval, committed where CBPAUP0C takes its checkpoints (CBPAUP0C-018, CBPAUP0C-019), as IMS commits at each `CHKP`.
- Today: the injected `Clock`, read once at the start and used as `YYDDD` (CBPAUP0C-001); tests use `FixedClock`.
- SYSOUT: each `DISPLAY` becomes one line of standard output, in program order. CBPAUP0C displays only its parameters, today's date, counts and `PA-ACCT-ID`. The replacement departs from the displayed bytes only where Cardholder Data Redaction requires it: `PRM-INFO` is unvalidated SYSIN text that can be or hold a card number, an SSN or a password, which may be any 1 to 8 printable characters, so `PARM RECEIVED` shows it as received only when it is the default card's 17 bytes or 17 spaces, and otherwise as 17 `*`; the default card's and an empty value's lines are unchanged (CBPAUP0C-003; X-CBPAUP0J-7).

## Reading the table

- Rule ID: `CBPAUP0C-<nnn>`, in the order in which the program first reaches the rule.
- A displayed line is written as its literal in backticks, then `+` and the item displayed after it; `DISPLAY` writes its operands with nothing between them. A literal's length is given where it ends in spaces or holds runs of spaces. "A line holding one space" is `DISPLAY ' '`.
- Displayed numbers: an unsigned `9(n)` item shows its n digits. A signed binary or packed item (`S9(8) COMP` counts, `PA-ACCT-ID PIC S9(11) COMP-3`) is converted to zoned decimal and shows its picture's digits with leading zeros and no sign character, for the non-negative values this program displays (X-CBPAUP0J-6). "8 digits" means, for example, `00000003`.
- Text comparisons: CBPAUP0C compares its counters with text parameters as text (X-CBPAUP0J-3). Such a comparison is written with the operands as the program compares them, the shorter padded with spaces, for example `00001000` > `00001   `.
- Replacement: where a row says how the replacement realises a COBOL effect (a table operation, a commit, an exit code), that sentence starts with "Replacement:".

- Cardholder Data Redaction: details carry `PA-CARD-NUM` (CIPAUDTY-005), but no row needs a card value, and this file holds none. The tests assemble their protected values at run time; no audit file or source line holds one.

- Total Parsers Over Untrusted Input: the `--sysin` value is external input; CBPAUP0C-002 makes its parse total, with a typed error for every value it does not accept.
- Typed Dates and Timestamps: no field here is an `X(10)` date or an `X(26)` timestamp; `YYDDD` values are integers.
- Money constraint and R1: amounts appear only in CBPAUP0C-013 and CBPAUP0C-014, through ARITH-047 and ARITH-048; nothing here involves floating point.
- Behaviour constraint: the duplicated condition (CBPAUP0C-016), the absent `REPL` (CBPAUP0C-017) and the text comparisons (CBPAUP0C-018, CBPAUP0C-020) are expected results, reproduced and never fixed.
