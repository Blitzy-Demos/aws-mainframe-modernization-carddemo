# CREASTMT audit: CBSTM03A and CBSTM03B, the account statements, and the statement PDF

This is the derive-lane (#2) audit of the batch job CREASTMT, its programs CBSTM03A and CBSTM03B, and the PDF conversion that TXT2PDF1 performs on its text output. The replacement runs all three as `carddemo-batch creastmt`. This file comes before `modern/crates/domain/src/batch/cbstm03a.rs`, `modern/crates/batch/src/jobs/creastmt.rs`, `modern/crates/batch/src/pdf.rs` and `modern/crates/batch/tests/creastmt.rs`, and code that consumes it is accepted only once the reviewer marks this file `Accepted` in the status table of `../README.md` (a8, a9; AAP 0.8.6). The statement bytes are the Statements success criterion (AAP 0.3.4.5), so every record is specified closely enough for a test to build the expected bytes from typed records. Every source was read in place at commit `59cc6c2` and none was changed (R16). Where the AAP's prose and the code differ, the code is authoritative and the difference is proposed below as an escalation candidate.

Jobs: `CREASTMT.JCL`, `TXT2PDF1.JCL` and `XREFFILE.jcl` in `app/jcl/`, read only and outside the source inventory (E22). Source lines use these short names; `BUILDBAT.prc` is `samples/proc/BUILDBAT.prc`.

- Arithmetic: `../arithmetic.md` assigns `ADD TRNX-AMT TO WS-TOTAL-AMT` to this file ("Statements outside the table") under its store rule; CBSTM03A-028 is that row.
- Fixture expectations: the scenario `POSTED` of `../fixtures.md`, whose FIXSTMT-001 to FIXSTMT-050 give each statement and FIXSTMT-901 to FIXSTMT-904 the files. This file states the rules those rows apply and repeats no fixture value.
- Compile options: `BUILDBAT.prc:35-36`, read only, compiles batch programs with `PARM=(APOST,LIST,MAP,NUMBER,NOSEQ)`: no `SSRANGE` (X-CREASTMT-H2).

## The job

- JCL: `DELDEF01` deletes and defines the work KSDS TRXFL; `STEP010` sorts the TRANSACT file and reformats it; `STEP020` loads the result into TRXFL with `REPRO`; `STEP030` deletes the previous run's statement files; `STEP040` runs CBSTM03A, which calls CBSTM03B for every file operation on TRXFL (`TRNXFILE`), the cross-reference file (`XREFFILE`), the customer file (`CUSTFILE`) and the account file (`ACCTFILE`), and writes `STMTFILE` and `HTMLFILE` itself. `STEP020` to `STEP040` carry `COND=(0,NE)`. The PDF is made by a separate job, TXT2PDF1 (`CREASTMT.JCL:22-96`; `TXT2PDF1.JCL:24-39`).
- Replacement: subcommand `creastmt` of `carddemo-batch`, with no options. It reads `transactions` (`card_num`, `tran_id`, `tran_desc` and `tran_amt`, ordered by card number, then transaction ID), `card_xref` in card-number order, and `customers` and `accounts` by key; it writes no table and never migrates.
- Outputs: three files in `CARDDEMO_STATEMENT_DIR` (default `./var/statements/`): `STATEMNT.PS`, 80-byte records each followed by LF; `STATEMNT.HTML`, 100-byte records each followed by LF; and `STATEMNT.PDF` (AAP 0.3.4.3, 0.3.4.5). The names are fixed, not GDG generations, and each run replaces the previous run's files (CBSTM03A-002). They stay on the local filesystem, with no object storage (AAP 0.3.4.4).
- Encoding: the COBOL writes EBCDIC; the replacement writes the same characters as ASCII bytes, the encoding of the fixtures. Every byte this file states is that character.
- SYSOUT: each `DISPLAY` becomes one line of standard output, in program order, except the control-block lines of CBSTM03A-003, which are not reproduced. On a normal end the standard output holds only the three paths (CBSTM03A-050).
- Exit status: 0 on a normal end; non-zero after any error line (CBSTM03A-049).

## Reading the table

- Rule ID: `CBSTM03A-<nnn>` in program order: the job's input and files (001–002), the start of the program (003–005), the transaction table (006–008), the main loop and its lookups (009–013), the text records (014–031), the HTML records (032–047), the end of the program (048–050), and the PDF (051–052, Program `TXT2PDF (batch::pdf)`, numbered in CBSTM03A's series because the converter is no program of this repository); then `CBSTM03B-<nnn>` (001–007), the file subroutine.
- Program: the program, or the utility a JCL step runs (`SORT`, `IDCAMS`, `IEFBR14`), with the job name.
- Records are written as their parts joined by `+`. Text in backticks is exact; a run of spaces or of one repeated character is written as its count ("31 `*`", "9 spaces"); a number in parentheses after a literal or a field is its length in bytes. "Padded" means right-padded with spaces to the record length, 80 for `STATEMNT.PS` and 100 for `STATEMNT.HTML`.
- "The first word of X" is the bytes of X before its first space: nothing when X starts with a space, all of X when it holds no space (`STRING … DELIMITED BY ' '`).
- "Up to its first double space" is the bytes before the first two consecutive spaces of the field, all of it when it holds none (`DELIMITED BY '  '`); "up to its first `*`" likewise (`DELIMITED BY '*'`).
- Edited amounts are rendered by `copybook::edited` (`EditedPicture::Nines9Dot99Minus` for `PIC 9(9).99-`, `EditedPicture::Z9Dot99Minus` for `PIC Z(9).99-`), never by the caller.
- "EBCDIC order" is the EBCDIC collating sequence the program compares and sorts in (X-CREASTMT-3).
- Replacement: where a row says how the replacement realises a COBOL effect (a query, a file operation, an exit status), that sentence starts with "Replacement:".

## How the rows are proved

- Every row is tagged `// audit: CBSTM03A-<nnn>` or `// audit: CBSTM03B-<nnn>` by `modern/crates/batch/tests/creastmt.rs`, which runs the subcommand against a testcontainers PostgreSQL migrated through `runtime::migrate` (`test_support::postgres`) and asserts the bytes of the three files, the standard-output lines, the files left in the directory and the exit status. The pure rules (the `STRING` rules, the edits, the total, each record's composition, the record order and the HTML literals) are also tagged in `modern/crates/domain/tests/batch_rules.rs`, over typed records given to `domain::batch::cbstm03a`.
- The fixture scenario is `POSTED` (FIXSTMT-001 to FIXSTMT-904). A row whose condition no fixture reaches (a missing customer or account, an empty `card_xref`, a blank name or address part, a `*` in a description, an overlong name, a balance of ten integer digits) is proved over rows the test inserts into its own database or over records built in memory; no fixture is edited or copied.
- Database failures (CBSTM03A-012) are provoked through a repository double that fails the named read (AAP 0.5.4).
- The CBSTM03B rows have no subroutine to test: they are proved by what the repository calls return to `creastmt` (order, keyed lookup, no row for the key).
- A case a halt candidate below names gets no parity assertion until the reviewer folds the candidate in or rejects it; its tagged test asserts the replacement's behaviour as the replacement's and reports the parity `BLOCKED`.

## Rules governing this file

- Cardholder Data Redaction: CBSTM03A reads `XREF-CARD-NUM` and `TRNX-CARD-NUM` only to match transactions to cross-reference records; no statement record carries a card number, an SSN, a CVV or a password (X-CREASTMT-5). The statements carry customer names and addresses, account IDs, balances, FICO scores and transaction details; they are local files, not egress, and no endpoint serves them (AAP 0.3.4.4). This file quotes no fixture value: fields are named, and per-statement expectations live in `../fixtures.md` by reference.
- Local-Only Runtime: the outputs stay in the configured local directory; the job needs only PostgreSQL.
- Money constraint and R1: amounts appear only in CBSTM03A-022, CBSTM03A-027 and CBSTM03A-028, through `MoneyExpr::store` and `copybook::edited`. `batch::pdf` receives only text bytes; its `f32` page positions are whole millimetres computed with integer arithmetic (CBSTM03A-051).
- Checked Integer Narrowing: the table counters (`CR-CNT`, `TR-CNT`, `WS-TRCT`, `PIC S9(4) COMP`) have no counterpart in the replacement's collections; the only narrowings are the stores of CBSTM03A-022 and CBSTM03A-028, which the `// TRUNCATION:` comments cite.
- Typed Dates and Timestamps: no date or timestamp field is consumed; `TRNX-ORIG-TS` and `TRNX-PROC-TS` travel in the table and are never written.
- Total Parsers Over Untrusted Input: the job decodes no external bytes; its inputs are typed rows. The PDF is read back only from bytes this code produced: by `batch::pdf`, from the document `printpdf` has just serialised in the same process (X-CREASTMT-8), and by the test, from the file the job wrote (E41).
- Behaviour constraint: the first-word `STRING` rules, the double-space and `*` truncations of the HTML text, the dropped high-order balance digit (X-CREASTMT-4) and the 51 × 10 table limits are expected results or halt candidates, reproduced or blocked and never fixed.
- R7 — Anomaly handling: anomalies are proposed below as `X-CREASTMT-<n>` and `X-CREASTMT-H<n>`, never normalised; a whitespace-only difference in the PDF text is escalated (CBSTM03A-052). R16: `app/**` and `samples/**` are read only.
