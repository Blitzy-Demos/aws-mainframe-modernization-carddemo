# MNTTRDB2 audit: COBTUPDT, the batch maintenance of the Db2 transaction types

This is the derive-lane (#2) audit of the batch job MNTTRDB2 and its program COBTUPDT, which the replacement runs as `carddemo-batch mnttrdb2`. It comes before `modern/crates/domain/src/batch/cobtupdt.rs`, `modern/crates/batch/src/jobs/mnttrdb2.rs` and `modern/crates/batch/tests/mnttrdb2.rs`, and code that consumes it is accepted only once the reviewer marks this file `Accepted` in the status table of `../README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16). Audited defects are expected results (Behaviour constraint).

MNTTRDB2 is in scope under rule (a) of AAP 0.2.3: the inventory names its program, but the dataset its `INPFILE` DD names is not in the repository. This file therefore also derives the job's test input, the record set COBTUPDT-101 to COBTUPDT-113, from COBTUPDT's record layout (X-MNTTRDB2-2).

## The job

- JCL: one step, `STEP1`, runs `IKJEFT01`, the TSO terminal monitor program in batch. Its `SYSTSIN` starts the DSN command processor on subsystem `DAZ1` and runs COBTUPDT under plan `CARDDEMO`, with no `END` after the `RUN` (X-MNTTRDB2-1). `INPFILE` is the only data input (X-MNTTRDB2-2). TSO and DSN write their own messages to `SYSTSPRT`; COBTUPDT's `DISPLAY` lines go to `SYSOUT`, which the step does not allocate (X-MNTTRDB2-9).
- Replacement: subcommand `mnttrdb2` of `carddemo-batch`, with the required option `--input`, a file of 53-byte records, each followed by LF; CRLF is accepted as a terminator, and the last record may have none (COBTUPDT-003, PIC-014). It reads and writes only `db2.transaction_type`, the Db2 data version (E23), which migration 0006 creates and seeds once; it never touches `transaction_types`, the VSAM data version that `tranrept` reads (COBTUPDT-026). It never migrates (Single Schema Executor). It exits 4 when any record failed and 0 otherwise (COBTUPDT-023), and with another non-zero status when the input cannot be read or decoded (COBTUPDT-004). It writes no file, so it prints no path (AAP 0.3.4.3).
- Job log: each `DISPLAY` becomes one line of standard output, in program order, as `CBPAUP0J.md` defines SYSOUT, with every byte the program displays, trailing spaces included. No line carries a card number or any other protected value, because the input layout holds none.

## Reading the table

- Rule ID: `COBTUPDT-<nnn>`, in two blocks. COBTUPDT-001 to COBTUPDT-027 are the rules, in the order the job first reaches them: the step and the input (001-003), the open and the read loop (004-006), the dispatch on the action byte (007-009), the insert, update and delete with their outcomes (010-018), the SQL error text (019-020), the message field, the return code and the unit of work (021-024), the end of the run (025), and the tables touched with the E23 cross-check (026-027). COBTUPDT-101 to COBTUPDT-113 are the derived test input (X-MNTTRDB2-2): 101 to 110 are the records of one `--input` file, in file order, run against a database freshly migrated (schema `db2` holds only migration 0006's seed), 111 is that run's end state, and 112 and 113 are two further runs, each on its own freshly migrated database.
- Program: `COBTUPDT`; `IKJEFT01 (MNTTRDB2 STEP1)` for the job step; `COBTUPDT; CBTRN03C` for the cross-check with TRANREPT.
- A record is written as its action byte, its two code bytes and its description text, then "space-padded to 50", with the total of 53 bytes; the test builds each record from that and writes it followed by LF. Descriptions are fictional.
- A job-log line is written as its literal in backticks, then `+` and the item displayed after it; `DISPLAY` writes its operands with nothing between them. A literal's length is given where it ends in a space or where its exact length matters. The 80 bytes of `WS-RETURN-MSG` are written as their text followed by "and n spaces".
- PostgreSQL outcomes stand for the Db2 SQLCODEs the program tests, as `../online/COTRTUPC.md` maps them, with `unique_violation` added for the insert: a statement that completes for SQLCODE 0; an `UPDATE` or `DELETE` that changes no row for `+100`; `unique_violation` (SQLSTATE `23505`) on the insert for `-803`; `foreign_key_violation` (`23503`) on the delete for `-532`; `deadlock_detected` (`40P01`) or `lock_not_available` (`55P03`) for `-911`; any other statement error for another negative SQLCODE. A lost database connection is X-MNTTRDB2-H2.
- Replacement: where a row says how the replacement realises a COBOL effect, that sentence starts with "Replacement:".

## How the rows are proved

- `modern/crates/batch/tests/mnttrdb2.rs` runs the subcommand against a testcontainers PostgreSQL migrated through `runtime::migrate` (`test_support::postgres`), with no load run. It writes the records of COBTUPDT-101 to COBTUPDT-110 to a scratch `--input` file and asserts the standard output line by line with trailing spaces, the exit status, and the contents of `db2.transaction_type` (with `octet_length(tr_description)`), `db2.transaction_type_category`, `transaction_types` and `transaction_categories` (COBTUPDT-111); it does the same for COBTUPDT-112 and COBTUPDT-113 on fresh databases. Each test carries `// audit: COBTUPDT-<nnn>` for the rows it proves.
- The pure rules (the record decode, the dispatch, the message texts and their overlay, the return code) are also tagged in `modern/crates/domain/tests/batch_rules.rs`, which drives `domain::batch::cobtupdt` with records the derived set does not hold: lower-case and blank action bytes, codes that are not digits, an error text followed by `No records found.`.
- The typed input errors of COBTUPDT-003 and COBTUPDT-004 are provoked with input files holding a 52-byte body, a 54-byte body, a CR inside a body, a control byte or a byte above 0x7E, and with a path that does not exist. The failure row COBTUPDT-014 and the `-911` case of COBTUPDT-024 are provoked through a repository double that fails the named statement with the SQLSTATE the mapping above names (AAP 0.5.4).
- COBTUPDT-027 is also tagged in `modern/crates/batch/tests/tranrept.rs`, which proves CBTRN03C-038 with the same run.
- COBTUPDT-005, marked `HALTED(X-MNTTRDB2-H1)`, and COBTUPDT-020, marked `HALTED(X-HALTS-2)`, are reported `BLOCKED` by their tagged tests and assert no value until the reviewer folds the candidate in or rejects it. A row that names a candidate without the marker stays provable for every other case.

## Rules governing this file

- Single Schema Executor: `mnttrdb2` expects the schema and the Db2 seed that `carddemo-migrate` applied through `runtime::migrate`; it never migrates, and the tests migrate only through `test_support::postgres` (COBTUPDT-026).
- Total Parsers Over Untrusted Input: the `--input` file is external input; its decode is total, with a typed error for every line it does not accept (COBTUPDT-003, COBTUPDT-004).
- Cardholder Data Redaction: COBTUPDT handles no card number, SSN, CVV or password, and the job-log lines echo only type codes and descriptions; the derived descriptions are fictional.
- Typed Dates and Timestamps, Checked Integer Narrowing, the Money constraint and R1: no field here is a date, a timestamp, an amount or an integer the replacement narrows; the only number is the Db2 SQLCODE, whose edited value is blocked (COBTUPDT-020).
- Local-Only Runtime: the input is a local file and the job writes no file.
- Behaviour constraint: the unvalidated code, the return code 4 for every failure, the message overlay and the commit at the end are expected results, reproduced and never fixed.
- R7 — Anomaly handling: anomalies are proposed below as `X-MNTTRDB2-<n>` and `X-MNTTRDB2-H<n>`, never normalised. R16: `app/**` is read only.
