# Load audit

This is the derive-lane (#2) audit of the nine load subcommands of `carddemo-batch`: the eight IDCAMS jobs that delete, define and REPRO a VSAM cluster from an ASCII fixture, and DUSRSECJ, which copies its in-stream records with IEBGENER and then loads them the same way. They are in scope under rule (b) of AAP 0.2.3: each loads an inventory fixture or its own in-stream data. This file comes before `crates/domain/src/batch/loads.rs`, `crates/batch/src/jobs/{loads,dusrsecj}.rs` and `crates/batch/tests/loads.rs`, and code that consumes it is accepted only once the reviewer marks it `Accepted` in the status table of `../README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16).

## Sources

- Jobs: `app/jcl/{ACCTFILE,CARDFILE,XREFFILE,CUSTFILE,DISCGRP,TCATBALF,TRANCATG,TRANTYPE,DUSRSECJ}.jcl` and the load order of `scripts/remote_refresh.sh:16-44`, read only and outside the source inventory (E22).
- Layouts: `app/cpy/{CVACT01Y,CVACT02Y,CVACT03Y,CVCUS01Y,CVTRA01Y,CVTRA02Y,CVTRA03Y,CVTRA04Y,CSUSR01Y}.cpy`, cited by their field and class rows in `../copybooks.md` rather than restated.
- Fixtures: the eight files of `app/data/ASCII/` the jobs load, and the in-stream records `app/jcl/DUSRSECJ.jcl:35-44`. Record counts, keys and per-record framing are in `../fixtures.md` (FIXFRM, FIXUSR and FIXLOAD rows); this file states the rules those rows apply and repeats no per-record expectation.
- Schema: `0001_reference_and_master.sql`, `0003_users.sql` and `0006_db2_transaction_types.sql`, which only `carddemo-migrate` applies, through `runtime::migrate`.

Source lines use short names: `.jcl` is in `app/jcl/`, `.cpy` in `app/cpy/`, `remote_refresh.sh` in `scripts/` and `.sql` in `modern/crates/persistence/migrations/`; `AAP 0.x` cites a section of the plan.

The subcommands, in `scripts/dev-up.sh` order, which is the order of `remote_refresh.sh:16-44` less TRANFILE (out of scope, AAP 0.2.3):

- `acctfile`: ACCTFILE, `acctdata.txt` → `accounts`.
- `cardfile`: CARDFILE, `carddata.txt` → `cards`.
- `xreffile`: XREFFILE, `cardxref.txt` → `card_xref`.
- `custfile`: CUSTFILE, `custdata.txt` → `customers`.
- `discgrp`: DISCGRP, `discgrp.txt` → `disclosure_groups`.
- `tcatbalf`: TCATBALF, `tcatbal.txt` → `tran_cat_balances`.
- `trancatg`: TRANCATG, `trancatg.txt` → `transaction_categories`.
- `trantype`: TRANTYPE, `trantype.txt` → `transaction_types`.
- `dusrsecj`: DUSRSECJ, the in-stream records of `app/jcl/DUSRSECJ.jcl` → `users`.

The eight fixture loads read `CARDDEMO_FIXTURE_DIR` (default `../app/data/ASCII`) `/<file>.txt`, or the file `--input` names. `dusrsecj` reads `app/jcl/DUSRSECJ.jcl` in place, as `../app/jcl/DUSRSECJ.jcl` from `modern/`, the working directory of every binary.

## How the rows are proved

- Every row is proved in `crates/batch/tests/loads.rs`, against a testcontainers PostgreSQL migrated through `runtime::migrate` (`test_support::postgres`), with the fixtures read in place through `test_support::fixtures`. Each test carries `// audit: LOADS-<nnn>` for the rows it proves.
- A row whose condition needs input no fixture holds (LOADS-013, LOADS-016, LOADS-017 and LOADS-019) is proved over a scratch file in the test's temporary directory, passed with `--input`, or through `domain::batch::loads` in `crates/domain/tests/batch_rules.rs`. No fixture is edited, and none is copied into the repository.
- A "no counterpart" row is proved by what the load leaves unchanged and by what it does not need: the catalog, every table but the target, the filesystem under `CARDDEMO_VAR_DIR`, and every service but PostgreSQL.

## Reading the table

- Rule ID: `LOADS-<nnn>`, in table order: the nine jobs in `dev-up.sh` order (001–009), the inputs (010–013), replacement (014–015), failures (016–019), schema (020–021), alternate indexes (022–024), independence of the loads (025–029), framing and FILLER (030–032), the USRSEC records (033–034), steps with no counterpart (035–037) and output (038–039).
- Program: the utility the JCL step runs (`IDCAMS`, `IEBGENER`, `IEFBR14` or `SDSF`), with the job name; a row that holds for several jobs names them all.
- Paragraph: the JCL step name; DUSRSECJ's steps differ from the other jobs' and are named separately.
- Copybook field or PIC: the record layout or field with its `../copybooks.md` rule IDs, and the `KEYS` and `RECORDSIZE` the step declares.
- Input condition and Expected result: what the subcommand is given, and what it leaves in PostgreSQL, on standard output and in its exit status.
- Steps with no PostgreSQL counterpart (the CEMT close and open of the CICS files, DEFINE PATH, BLDINDEX, the IEFBR14 pre-delete and `REUSE`) have rows stating "no counterpart; no effect", so the reviewer sees each was considered; each still names what a test observes.
- "Migrated database": a database `carddemo-migrate` has migrated. "Loaded": migrated, with rows in the target table. "Empty": migrated, with none.

## Rules governing this file

- Single Schema Executor: every load runs against a schema `carddemo-migrate` has already applied and never migrates (LOADS-020, LOADS-021).
- Typed Dates and Timestamps: the five `X(10)` dates the loads carry are typed by PIC-015 and PIC-016 and stored as `DATE` (LOADS-001, LOADS-002, LOADS-004); no loaded field is a timestamp.
- Total Parsers Over Untrusted Input and R7 — Anomaly handling: malformed input bytes give a typed error, which fails the load and is escalated; never a panic, a default or a skipped record (LOADS-013, LOADS-016, LOADS-017).
- Cardholder Data Redaction: no card number, SSN, CVV or password value appears here. Fields are named (`CARD-NUM`, `XREF-CARD-NUM`, `CUST-SSN`, `CARD-CVV-CD`, `SEC-USR-PWD`) and records cited as `file:line`. The loads store card numbers, CVVs and SSNs in full, as the copybooks hold them, and the password only as a hash (E25); no load writes any of them to standard output, a tracing event or an error (LOADS-016, LOADS-018, LOADS-033, LOADS-039).
- R16 — Authority and protected paths: `app/**` and `scripts/**` are read in place, and nothing there is changed (LOADS-011).

## Escalation candidates

Proposed under R7 — Anomaly handling. The reviewer folds each candidate into `../ESCALATIONS.md` under its next free ID, as that file's `## Later entries` section describes; until then the rows above cite the candidate names.

- `X-LOADS-1`
  - Found in: the REPRO statements `app/jcl/ACCTFILE.jcl:61`, `app/jcl/CARDFILE.jcl:75`, `app/jcl/XREFFILE.jcl:64`, `app/jcl/CUSTFILE.jcl:71`, `app/jcl/DISCGRP.jcl:61`, `app/jcl/TCATBALF.jcl:61`, `app/jcl/TRANCATG.jcl:61`, `app/jcl/TRANTYPE.jcl:61` and `app/jcl/DUSRSECJ.jcl:87`.
  - Anomaly class: request-vs-repository.
  - Finding: what REPRO does with a record whose key duplicates or precedes the previous record's is defined by IDCAMS, not by the repository, which holds only the REPRO statements: IDCAMS reports such a record and loads the others, up to the error limit it applies, so the cluster ends up holding the records it accepted. The replacement replaces the table in one transaction (AAP 0.3.3.4) and cannot keep some records while refusing others. No fixture reaches the case (FIXFRM-020).
  - Proposed resolution: LOADS-017: the load fails before any write and leaves the previous contents. This is not a parity result for that case, and no binding asserts one.
- `X-LOADS-2`
  - Found in: `app/jcl/ACCTFILE.jcl:22-62`, `app/jcl/CARDFILE.jcl:33-76`, `app/jcl/XREFFILE.jcl:22-65`, `app/jcl/CUSTFILE.jcl:32-72`, `app/jcl/DISCGRP.jcl:22-62`, `app/jcl/TCATBALF.jcl:22-62`, `app/jcl/TRANCATG.jcl:22-62`, `app/jcl/TRANTYPE.jcl:22-62` and `app/jcl/DUSRSECJ.jcl:58-88`.
  - Anomaly class: request-vs-repository.
  - Finding: each job deletes and redefines the cluster in steps that complete before REPRO reads its input, and no step carries a `COND` parameter. A REPRO that stops on an error, or whose input DD cannot be allocated, therefore leaves an empty or partly loaded cluster behind. The replacement fails before it writes or rolls its single transaction back, so every failure leaves the previous contents.
  - Proposed resolution: LOADS-016, LOADS-018 and LOADS-019, as AAP 0.3.3.4 requires; the empty or partial state is not reproduced. No fixture load fails, so no parity result depends on it.
- `X-LOADS-3`
  - Found in: `modern/crates/persistence/migrations/0001_reference_and_master.sql:116-121` against `app/jcl/CARDFILE.jcl:33-76`.
  - Anomaly class: refinement-override.
  - Finding: `cards.card_ref` exists because Cardholder Data Redaction takes card numbers out of the API's list rows and page keys (E32). It is an identity column, so every `cardfile` run gives every card a new value, while the COBOL card list keys by `CARD-NUM`, which a reload never changes. A screen that holds a `card_ref` from before a reload names no card afterwards.
  - Proposed resolution: LOADS-027: kept. `card_ref` is excluded from the rerun comparison (LOADS-026), and endpoints 8 to 10 treat an unknown `card_ref` as their program treats a card that is not found, with the message their online audits fix.
- `X-LOADS-4`
  - Found in: `app/jcl/DUSRSECJ.jcl:23-26,46-49,62-67`.
  - Anomaly class: request-vs-repository.
  - Finding: DUSRSECJ stages its records in the sequential dataset `AWS.M2.CARDDEMO.USRSEC.PS`, which PREDEL deletes before IEBGENER catalogs it again and which stays catalogued after the job, and defines the cluster with `REUSE`. - `X-LOADS-5`
  - Found in: the REPRO statements cited by `X-LOADS-1`.
  - Anomaly class: request-vs-repository.
  - Finding: the condition code REPRO ends with for an input holding no record is defined by IDCAMS, not by the repository, and no fixture is empty. Without a rule, an empty or truncated input file would replace a master table with no rows.
