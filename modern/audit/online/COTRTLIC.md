# COTRTLIC — transaction type list (CTLI)

This is the derive-lane (#2) audit of `COTRTLIC` (2,098 lines), transaction `CTLI`, map `CTRTLIA` of mapset `COTRTLI`: the admin list of the Db2 data version of the transaction types (`db2.transaction_type`, never the VSAM version, E23), with forward and backward paging, a single-row update or delete, and a confirmation step on F10. It is written before `modern/crates/domain/src/online/cotrtlic.rs`, `modern/crates/api/src/services/cotrtlic.rs`, `modern/crates/api/src/dto/cotrtlic.rs`, `modern/crates/api/src/handlers/cotrtlic.rs`, the Db2-version page queries in `modern/crates/persistence/queries/` and `modern/crates/api/tests/endpoints_transaction_types.rs`, which are accepted only once this file is `Accepted` in the status table of `modern/audit/README.md` (a9). The COBOL is read in place at commit `59cc6c2` and never modified (R16).

## Reading the table

Endpoints (AAP 0.3.4.1), both behind the admin gate:

- Endpoint 24, `GET /api/v1/transaction-types`, `TranTypeListQuery { type_filter?, desc_filter?, page_key?, direction?, page_size? }` → `TranTypeListResponse` (seven rows of the Db2 data version, the page number, `state`): the screen load (no `page_key`) and F7 or F8 (`direction` backward or forward).
- Endpoint 25, `POST /api/v1/transaction-types/list-actions`, `TranTypeListActionRequest { aid: ENTER or PF10, type_filter, desc_filter, rows: 7 × { selection, description }, state, page_size? }` → `TranTypeListActionResult` (the page, per-row errors, the messages, the new `state`): ENTER and F10.
- F2 and F3 call no endpoint (`client` rows).

`TranTypeListState` is the program's own COMMAREA, `WS-THIS-PROGCOMMAREA` (`COTRTLIC.cbl:377-418`), which the server returns with every response and the client echoes unchanged:

- the filters of the displayed page, as typed: `WS-CA-TYPE-CD PIC X(02)` and `WS-CA-TYPE-DESC PIC X(50)`;
- the seven rows as the last read returned them, code and description (`WS-CA-EACH-ROW-OUT`, 7 × 52 bytes); on a `U` row with an edited description the screen shows the edited text instead (X-COTRTLIC-9);
- the selected row, a position from 1 to 7, 0 for none (`WS-CA-ROW-SELECTED`);
- the first and last keys (`WS-CA-FIRST-TR-CODE`, `WS-CA-LAST-TR-CODE`), the page number (`WS-CA-SCREEN-NUM PIC 9(1)`), the next-page indicator (`WS-CA-NEXT-PAGE-IND`) and the last-page indicator (`WS-CA-LAST-PAGE-DISPLAYED`);
- the pending action: a delete flag and an update flag (`WS-CA-DELETE-FLAG`, `WS-CA-UPDATE-FLAG`), which can both be set (COTRTLIC-043).

The state carries no authority. The admin gate is the verified token (COTRTLIC-001), every request re-runs every edit, and every commit is a keyed `UPDATE` or `DELETE` whose not-found outcome has a row of its own (COTRTLIC-046, COTRTLIC-051).

Columns:

- Paragraph: the paragraph that decides the outcome; `→` marks a paragraph it performs.
- Copybook field or PIC: the working-storage, COMMAREA, map or host-variable fields the rule reads or sets.
- Input condition: the request and the state. "The filters" are the type filter and the description filter; "changed" and "unchanged" are as COTRTLIC-029 and COTRTLIC-030 define them.
- Expected result: the response (rows, page number, messages, `state`) and the store effects. "Error message" is the map's `ERRMSG` line (row 23) and "info" its `INFOMSG` line (row 21). Literals are exact; a literal inside a longer message is shown with its own spaces.
- Status: 400 input error; 401 and 403 the gate; 404 a row another user deleted; 500 store failure; 200 every response without an error, including one whose error line carries a non-error message (`No change detected with respect to database values.` or a paging message). The README leaves two choices open, made here: a deadlock (`SQLCODE` −911) is 500, because the README keeps 409 for a record another user changed and nothing was changed; a delete restricted by categories (`SQLCODE` −532) is 400, because the program asks the user to correct the request. On endpoint 25 a 4xx or 5xx answer still carries what the COBOL re-sends with the message (the page, the per-row errors and `state`), since the program sends the whole screen with every message (`COTRTLIC.cbl:699-720`); only COTRTLIC-001 and COTRTLIC-053 send no screen.
- The rows describe the default page of seven rows (`WS-MAX-SCREEN-LINES`); "Rules governing this file" covers `page_size`.

## Rules governing this file

- Bounded Pagination: the default page is seven rows, `WS-MAX-SCREEN-LINES`. `page_size` and the rejection of an out-of-range value are not COBOL behaviour and have no row here; the screen never sends `page_size`, and a value from another caller changes only how many rows a page holds, which no parity claim covers. Every page read is a range or an equality on `tr_type` ordered by `tr_type`, served by the primary key `xtran_type`; the cross-edit count of COTRTLIC-031 is not a page.
- Equivalence failure and H3: the text after ` SQLCODE:` in every Db2 message is `HALTED(H3)` (COTRTLIC-055); the rows that raise those messages assert only their prefix, status and store effects and cite "halt H3". The halt candidates below get no parity assertion until the reviewer folds them in.
- Behaviour constraint and R7 — Anomaly handling: E28 is preserved (COTRTLIC-019). Every other anomaly found is proposed under `## Escalation candidates` or `## Halt candidates`, and the rows state the COBOL's result, never a corrected one.
- Identity and Trust (AAP 0.5.1): the acting identity and the admin gate come only from the verified token; `state` and every request field are input.
- Thin Request Handlers: the workflow these rows describe belongs to `domain::online::cotrtlic` and `api::services::cotrtlic`; the handler only extracts, calls and maps.
- Cardholder Data Redaction and Typed Dates and Timestamps are not engaged: the program handles no card number, SSN, CVV, password, date or timestamp.
- R16 — Authority and protected paths: `app/**` is read only, and this file is the only output.
