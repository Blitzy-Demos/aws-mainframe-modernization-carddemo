# COSGN00C — sign-on (CC00)

This is the derive-lane (#2) audit of `app/cbl/COSGN00C.cbl` (260 lines), the sign-on program of transaction `CC00` and map `COSGN00` (`COSGN0A`). Its replacement is endpoint 1, `POST /api/v1/signon`, the only operation that requires no token: `SignonRequest` (user ID, password) → `SignonResponse` (`token`, user ID, user type, `next_route`), or `ScreenError { message, field }` with the HTTP status each row gives (AAP 0.3.4.1, 0.3.4.6). The screen is `modern/frontend/src/screens/COSGN00.tsx` at route `/signon`. The rows come before `crates/domain/src/online/cosgn00c.rs`, `crates/api/src/services/cosgn00c.rs`, `crates/api/src/handlers/cosgn00c.rs`, `crates/api/src/auth/{jwt,extract}.rs` and the tests that bind them, and code that consumes them is accepted only once this file is `Accepted` in the status table of `modern/audit/README.md` (a8, a9). The password is stored as typed and compared upper-cased (E26); that behaviour is preserved.

## Reading the table

- Rule ID: `COSGN00C-<nnn>`, numbered in program order from `001`.
- Paragraph: the COSGN00C paragraph that holds the rule; `A → B` names the paragraph `A` performs.
- Input condition: the AID key or the request that reaches the paragraph, and the state that selects the branch. A field is blank when it is empty, omitted from the request, or all spaces: the 3270 counterparts are an unmodified field (`LOW-VALUES`) and a field of spaces.
- Expected result: the HTTP status, the message literal exactly as the program moves it, in single quotes with its spacing, and the field the error names, which is the field the program puts the cursor on (`MOVE -1 TO USERIDL` → `user_id`, `MOVE -1 TO PASSWDL` → `password`); then the store and identity effects. Outcomes are those of the sign-on service; how the handler maps them is not part of a row (Thin Request Handlers).
- Layer: `server` rows are observable through endpoint 1; `client` rows send no request. No row is `both`. The COSGN00 zod schema repeats only the map `LENGTH` of the two inputs, which `screens.md` audits as `both` (`COSGN00-027`, `COSGN00-031`); it repeats neither blank-field edit, so the program's messages reach the screen from the server unchanged.

## Escalation candidates

Proposed under R7 — Anomaly handling. The reviewer folds each candidate into `ESCALATIONS.md` under its next free ID, as its `## Later entries` section describes; until then the rows above cite the candidate names.

- `X-COSGN00C-1`
  - Found in: `app/cbl/COSGN00C.cbl:132-134,211-216`; `app/cbl/COUSR01C.cbl:154`.
  - Anomaly class: declaration-not-followed.
  - Finding: sign-on upper-cases the user ID and reads USRSEC by it, while COUSR01C stores the user ID as typed. A user added with a lower-case letter in the ID can therefore never be found; this is the user-ID counterpart of E26. No in-stream user ID holds one (`app/jcl/DUSRSECJ.jcl:35-44`).
  - Proposed resolution: preserved. Every sign-on of such a user gets `'User not found. Try again ...'` (`COSGN00C-019`); the key is never compared case-insensitively. The same case is proposed from the storing side as `X-COUSR01C-1` in `online/COUSR01C.md`; the two are folded into one escalation.
- `X-COSGN00C-2`
  - Found in: `app/cbl/COSGN00C.cbl:221-223,252-256`; `app/cpy/CSUSR01Y.cpy:21`.
  - Anomaly class: request-vs-repository.
  - Finding: the COBOL compares two 8-byte fields, a test that cannot fail to run. The replacement verifies against an argon2id PHC string (E25), which can fail for a reason other than a mismatch: a `password_hash` that does not parse or names unsupported parameters. No COBOL path corresponds.
  - Proposed resolution: treated as the `WHEN OTHER` branch of `READ-USER-SEC-FILE`: HTTP 500 `'Unable to verify the User ...'`, field `user_id`, no token (`COSGN00C-020`), with a tracing event that carries neither the hash nor the password. It is never reported as `'Wrong Password. Try again ...'`, which would invite retries of a credential that cannot verify. Not a parity result.
- `X-COSGN00C-3`
  - Found in: `app/bms/COSGN00.bms:156-160,175-180`; `app/cbl/COSGN00C.cbl:132-136`; `app/cpy/CSUSR01Y.cpy:18,21`.
  - Anomaly class: request-vs-repository.
  - Finding: a 3270 field carries at most 8 single-byte characters of the terminal's code page, while a JSON string can carry any Unicode text: control characters, NUL, characters outside ASCII, or 8 characters that take more than 8 bytes in UTF-8. `USERIDI` and `PASSWDI` hold 8 bytes, and what `FUNCTION UPPER-CASE` does to letters outside a–z depends on a code page the repository does not fix.
  - Proposed resolution: endpoint 1 accepts in each field at most 8 characters, each printable ASCII (0x20–0x7E), the bytes a stored USRSEC field holds (`PIC-001`, `PIC-002`). Any other value gets the input rejection the request DTO gives an over-length value (`COSGN00-027`, `COSGN00-031`: HTTP 400 naming the field). Upper-casing maps a–z to A–Z and leaves every other byte unchanged. An empty or omitted field is the unmodified field (`LOW-VALUES`) and gets the blank-field message (`COSGN00C-007`, `COSGN00C-008`).

## Halt candidates

- `X-COSGN00C-H1`, proposed to join H2 (runtime storage initialisation).
  - Path: `app/cbl/COSGN00C.cbl:50,91-94,145-157`; `app/cpy-bms/COSGN00.CPY:17,67-78,85,140,146` (`COSGN0AO REDEFINES COSGN0AI`, no `VALUE` clause).
  - Why no single result: on the `WHEN OTHER` path no `RECEIVE MAP` runs and no statement sets `USERIDO`, `PASSWDO`, their attribute bytes `USERIDA` and `PASSWDA`, or the length fields `USERIDL` and `PASSWDL`. `SEND MAP ... ERASE CURSOR` then sends the task's copy of the symbolic map in WORKING-STORAGE, so what the user ID and password fields show after an invalid key, the attributes they get and where the cursor lands depend on runtime storage initialisation, which nothing in the repository sets. The typed input is not received on this path and is erased from the screen, so keeping it is not the COBOL's result either.
  - Bindings blocked: the client assertions of `COSGN00C-005` on the user ID and password inputs and the cursor after an invalid key (`screens/COSGN00.test.tsx`, NAV). The message, its error styling and the absence of a request stay assertable.
  - Escalation: none yet; the reviewer adds one to `ESCALATIONS.md` when folding the candidate in.
  - Candidate resolution: as H2, Language Environment storage-initialisation documentation for the deployed runtime options, or user descoping.
