# COUSR00C — user list (CU00)

This is the derive-lane (#2) audit of COUSR00C, the CICS program of transaction `CU00` that lists the users of the USRSEC file ten per page on map `COUSR0A` of mapset `COUSR00`. The replacement serves it as endpoint 16, `GET /api/v1/users` [A], with `UserListQuery { start_user_id?, page_key?, direction?, page_size? }` → `UserListResponse` (10 rows), and as the screen `COUSR00` at route `/users`. The rows below are the expected results for `crates/domain/src/online/cousr00c.rs`, `crates/api/src/services/cousr00c.rs`, the user page query in `crates/persistence/queries/`, `crates/api/src/{dto,handlers}/cousr00c.rs`, `crates/api/tests/endpoints_users.rs`, `frontend/src/screens/COUSR00.tsx` and NAV. Code that consumes this file is accepted only once the reviewer marks it `Accepted` in the status table of `modern/audit/README.md` (a9).

## Endpoint and paging state

- Endpoint 16 serves ENTER (with the search field), F7 and F8. F3, the row selections and the keys the program does not serve send no request (AAP 0.3.4.1).
- COUSR00C keeps its paging state between interactions only in the COMMAREA: the first and last user IDs of the page shown, the page number and the next-page indicator (COUSR00C-006). Every response returns them, and an F7 or F8 request carries them back as the response left them: `page_key` is the first user ID for F7 (`direction` backward) and the last user ID for F8 (`direction` forward), and the page number and next-page indicator travel with it. The state is request data and grants nothing (AAP 0.5.1).
- Page size: the COBOL page is fixed at ten rows (the map's ten row groups, the loops to `WS-IDX > 10` and `WS-IDX >= 11`). `page_size` defaults to 10, and the screen never sends it. Its bound and its rejection belong to Bounded Pagination, not to the COBOL, so no row here audits them. The page query is served by `users_pkey`, ascending for F8 and ENTER and descending for F7.
- Statuses: every page, and every message that comes with a page or with the unchanged paging state, is status 200, including `You are already at the top of the page...` and `You are already at the bottom of the page...`: F7 changes the paging state even when it reads nothing (COUSR00C-021), so that response must carry the state, which a `ScreenError` cannot. Store failures are 500, the admin gate 401 and 403, and a search value longer than the map's 8 characters 400 (COUSR00-015).
- One response per interaction: the COBOL can send the map twice in one interaction (a read paragraph sends at end of file or on not-found, then `PROCESS-PAGE-FORWARD` or `PROCESS-PAGE-BACKWARD` sends again). Each expected result is what the last send shows, the screen the terminal ends with.
- Messages: `WS-MESSAGE PIC X(80)` is cleared at the start of each interaction (`COUSR00C.cbl:105`), each later move replaces it, and the last one moved is shown in the 78-character error row.

## Reading the table

- Layer as `modern/audit/README.md` defines it: `server` rows are observable through endpoint 16, `client` rows send no request. No row is `both`: the only edit the screen repeats, the 8-character length of the search field, is `COUSR00-015` in `screens.md`.
- "The fixture" is the ten users of `DUSRSECJ.jcl:35-44`: `ADMIN001` to `ADMIN005` (type `A`) and `USER0001` to `USER0005` (type `U`), in that key order. User IDs are not protected values; names are not quoted.
- Keys are compared and ordered as 8-byte values, by byte (X-COUSR00C-2).
- `HALTED(X-COUSR00C-Hn)` marks a row whose result a halt candidate blocks; no parity value is asserted for it.
