# COCRDSLC — credit card detail (CCDL)

This is the derive-lane (#2) audit of `app/cbl/COCRDSLC.cbl` (887 lines), the CICS program behind transaction `CCDL` and map `CCRDSLA` of mapset `COCRDSL`. Endpoint 8, `GET /api/v1/cards/view`, replaces it: it takes `CardLookupQuery { acct_id, card_num? or card_ref? }`, exactly one of the two card inputs, and answers `CardViewResponse`, or `ScreenError { message, field? }` with the status each row gives. The file comes before `crates/domain/src/online/cocrdslc.rs`, `crates/api/src/services/cocrdslc.rs`, `crates/api/src/dto/cocrdslc.rs`, `crates/api/src/handlers/cocrdslc.rs` and the COCRDSLC tests of `crates/api/tests/endpoints_cards.rs`, and code that consumes it is accepted only once the reviewer marks it `Accepted` in the status table of `modern/audit/README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16).

## Reading the table

- Rule ID: `COCRDSLC-<nnn>`, numbered in the order of the program's flow: entry and keys, the edits, the read, the response, the screen, then the declared texts no path uses.
- Request fields: `acct_id` carries the account input `ACCTSID`, `card_num` the card input `CARDSID`, and `card_ref` the handle of a COCRDLIC list row (`cards.card_ref`, CVACT02Y-008). `ScreenError.field` names `acct_id` or `card_num`.
- An input is **blank** when it is absent, empty, all spaces, `*` alone, or all zero digits (11 for the account, 16 for the card): `2200-EDIT-MAP-INPUTS` turns `*` and spaces into LOW-VALUES (lines 614-627), and the edits treat LOW-VALUES, spaces and a zero value alike as not supplied (lines 651-653, 691-693). An account is **valid** when it is exactly 11 ASCII digits, not all zero; a card number when it is exactly 16 ASCII digits, not all zero. Any other input holds a byte that is not a digit; an input shorter than its field is one of them, because the terminal pads the field with blanks (`JUSTIFY` omitted on a field without `NUM`, `COCRDSL.bms:84-100`), and the replacement pads it the same way.
- Messages are quoted exactly as the program moves them, with the status the endpoint returns: 400 input error, 404 not found, 500 store failure. A response carries no error message when the row names none.
- Layer: no row is `both`. COCRDSL's zod schema enforces the map lengths only (`COCRDSL-013` and `COCRDSL-016` of `screens.md`, which are `both` there) and repeats none of COCRDSLC's edits, because their precedence (account first, the first error's text stands, then the cross-field override) is the endpoint's to decide and the server message wins (AAP 0.4.2).
- H4 binds only COCRDSLC-017 in this file: the two code fields of the file-error text are `HALTED(H4)`. COCRDSLC's not-found text embeds no CICS code (lines 153-154, 755-761), so COCRDSLC-015 asserts it, and COCRDSLC-016 cites the halt for the parts it leaves assertable.

## Rules governing this file

- Cardholder Data Redaction: endpoint 8 is the single operation that may return a full card number, and only for `usr_type` `A` (COCRDSLC-022); every other user gets the redacted form (COCRDSLC-023). This file quotes no card number; the redacted form is written `************` followed by the last four digits. A typed `card_num` in the query string is request input, not egress; request spans record the `MatchedPath` route template and never the query string (AAP 0.3.4.7), and no message of this program interpolates a card number.
- Identity and Trust (AAP 0.5.1): the disclosure reads only the verified token's `usr_type`; no request field and no COMMAREA copy can ask for it.
- Thin Request Handlers: the `card_ref` lookup, the read and the disclosure branch live in `api::services::cocrdslc`, the edits and the message texts in `domain::online::cocrdslc`; the handler extracts, calls the service and maps the outcome.
- Typed Dates and Timestamps: `CARD-EXPIRAION-DATE` travels as a typed date (COCRDSLC-019); the screen splits it into the parts the map shows (COCRDSLC-024).
- Bounded Pagination: endpoint 8 returns a single resource and takes no `page_size`.
- Equivalence failure and R7 — Anomaly handling: a halted part asserts nothing (H4 and the candidates `X-COCRDSLC-H1` and `X-COCRDSLC-H2`); audited defects are expected results (`X-COCRDSLC-1`); anomalies are proposed below, never smoothed over. ## Halt candidates

- `X-COCRDSLC-H1`, proposed as a new halt (H7 onward), shared with the programs that carry the same edit.
  - Path: `app/cbl/COCRDSLC.cbl:651-653,665` and `691-693,706`. `2210-EDIT-ACCOUNT` and `2220-EDIT-CARD` test `CC-ACCT-ID-N EQUAL ZEROS` and `CC-CARD-NUM-N EQUAL ZEROS`, the `9(11)` and `9(16)` redefinitions of the inputs, before the `IS NOT NUMERIC` class test. For an input that is neither blank nor all digits, that numeric comparison runs on invalid zoned-decimal data. Every input shorter than its field is such a case, because the terminal pads the field with blanks (`app/bms/COCRDSL.bms:84-100`). The same tests stand at `app/cbl/COCRDLIC.cbl:1009,1044` and `app/cbl/COCRDUPC.cbl:727,770`; COACTUPC's account edit tests `IS NOT NUMERIC` before the zero test (`app/cbl/COACTUPC.cbl:1802-1803`) and is not a case of this candidate.
  - Why no single result: IBM Enterprise COBOL gives no defined result for a numeric operation on invalid data; what the comparison does depends on the `NUMPROC` and `NUMCHECK` compiler options and the comparison the compiler generates, and no compiler option exists anywhere in the repository. The comparison can find the value zero (for bytes whose low half-byte is zero, such as `0` followed by blanks), and the input is then treated as not supplied (`'Account number not provided'`, `'Card number not provided'`, or `'No input received'` with the other input blank); it can find the value non-zero, and the class test then moves `'ACCOUNT FILTER,IF SUPPLIED MUST BE A 11 DIGIT NUMBER'` or `'CARD ID FILTER,IF SUPPLIED MUST BE A 16 DIGIT NUMBER'`; or it can raise a data exception that ends in `ABEND-ROUTINE`.
  - Bindings blocked: g1b: COCRDSLC-011 and COCRDSLC-012. NAV and the render test: the empty-in-red case of COCRDSLC-027, whose other cases stay assertable.
  - Escalation: none yet; the reviewer adds one to `ESCALATIONS.md` when folding the candidate in.
  - Candidate resolution: IBM Enterprise COBOL documentation of the compiler options of the deployed build (`NUMPROC`, `NUMCHECK`) and of the comparison they generate, or user descoping.
