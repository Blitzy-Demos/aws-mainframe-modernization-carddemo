# COACTVWC — account view audit

This is the derive-lane (#2) audit of COACTVWC, the CICS program of transaction `CAVW` (`app/cbl/COACTVWC.cbl`, 941 lines). The replacement serves it as endpoint 4, `GET /api/v1/accounts/{acct_id}/view` → `AccountViewResponse`, and as the screen `COACTVW` at route `/accounts/view`. The file records every rule the program applies to the account number, its three reads, its messages with their HTTP status, the fields it displays and the keys it serves. It comes before `modern/crates/domain/src/online/coactvwc.rs`, `modern/crates/api/src/services/coactvwc.rs`, `modern/crates/api/src/dto/coactvwc.rs`, `modern/crates/api/src/handlers/coactvwc.rs`, `modern/crates/api/tests/endpoints_accounts.rs` and the COACTVW screen and its tests, and code that consumes it is accepted only once the reviewer marks this file `Accepted` in the status table of `README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16).

Map `COACTVW.bms` in `app/bms/`; symbolic map `COACTVW.CPY` in `app/cpy-bms/`.
- Read only, outside the source inventory (E22): `XREFFILE.jcl` in `app/jcl/` and `CARDDEMO.CSD` in `app/csd/`, which define `CXACAIX` as the path over the cross-reference's non-unique alternate index on account ID.
- Field widths, types and columns: the rule IDs of `copybooks.md`; screen fields: the `COACTVW-<nnn>` rows of `screens.md`. Both are cited in the fourth column, `Copybook field or PIC`.
- Vendor rules the reviewer confirms: IBM CICS `READ` (conditions `NORMAL`, `NOTFND` and `DUPKEY`) and `RECEIVE MAP` (`MAPFAIL`); IBM Enterprise COBOL `MOVE` (an alphanumeric receiver keeps the leftmost characters; a numeric-edited receiver drops the integer digits it has no room for), `STRING` (stops at the end of the receiving field when no `ON OVERFLOW` is coded), `INITIALIZE` (FILLER items keep their values) and the `NUMERIC` class test (every character one of the digits `0` to `9`).

## Reading the table

- Rule ID: `COACTVWC-<nnn>`, in source order: `0000-MAIN` 001–005, `1100-SCREEN-INIT` 006, `1200-SETUP-SCREEN-VARS` 007–027, `1300-SETUP-SCREEN-ATTRS` 028, `2200-EDIT-MAP-INPUTS` and `2210-EDIT-ACCOUNT` 029–032, `9000-READ-ACCT` 033, `9200-GETCARDXREF-BYACCT` 034–039, `9300-GETACCTDATA-BYACCT` 040–043, `9400-GETCUSTDATA-BYCUST` 044–047, then `0000-MAIN` 048 (the re-entry case of halt candidate `X-COCRDSLC-H2`), numbered after the others because IDs are never renumbered.
- Request: the `acct_id` path parameter is the raw text of the 11-byte `ACCTSID` field, at most 11 characters (COACTVW-013), right-padded with spaces to 11 before the edit and never parsed as a number by the request DTO, so the program's edit and its messages are reproduced.
- Account block: the values of COACTVWC-010 to COACTVWC-015. Customer block: the values of COACTVWC-016 to COACTVWC-026. Both belong to `AccountViewResponse`.
- Messages and message pieces are quoted exactly as the program moves them, in single quotes with their spacing. A message is the 75-byte `WS-RETURN-MSG` without its trailing spaces, and "positions a-b" count from 1 in that field. Errors are `ScreenError { message, field? }` with status 400 for a failed input edit, 404 for a record not found and 500 for a read that fails otherwise; `field` is `acct_id` exactly when the program turns the account-number field red (COACTVWC-028).
- "Fails other than not found" is the CICS `WHEN OTHER` branch of a read: in the replacement, an error the repository returns. COACTVWC-039 adds the one data condition that reaches the same branch.
- "A `card_xref` row has the account ID" means a row whose `acct_id` equals the 11-digit key; the account and customer reads are by primary key.

## Paths without a row

- The `WHEN OTHER` branch of the main `EVALUATE` (lines 375-382: `'UNEXPECTED DATA SCENARIO'`, then `SEND-PLAIN-TEXT`) runs only when `CDEMO-PGM-CONTEXT` is neither 0 nor 1. COMEN01C, the only program that transfers here (`COMEN02Y.cpy:28`), moves zero to it (`COMEN01C.cbl:183`). Whichever branch of the first-entry test runs (lines 282-293), the context is 0 or 1: the `INITIALIZE` sets it to zero, and the `ELSE` moves in the received COMMAREA, which holds the menu's zero or the 1 that this program's own send sets (line 581) before every `RETURN` that passes a COMMAREA. The branch is unreachable, and the replacement has no COMMAREA context.
- `SEND-PLAIN-TEXT` (lines 877-890) is performed only from that branch. `SEND-LONG-TEXT` (lines 896-909) is never performed: its three `PERFORM` statements are commented out (lines 768, 818 and 867), and `WS-LONG-MSG` is never set.
- Lines 387-392 never run: every branch before them ends in `GO TO COMMON-RETURN`, an `XCTL` or the `RETURN` inside `SEND-PLAIN-TEXT`. The second `0000-MAIN-EXIT` paragraph (lines 411-413) repeats the first (lines 408-410), and no `PERFORM … THRU` names either.
- `COMMON-RETURN` (lines 394-407) saves the COMMAREA and returns with `TRANSID(CAVW)`: pseudo-conversational state with no counterpart, because the screen keeps its own state and the token carries the identity (AAP 0.5.1).
- `ABEND-ROUTINE` (lines 916-937), armed by `HANDLE ABEND` (lines 264-266), moves `'COACTVWC'` to `ABEND-CULPRIT` (line 922), sends the 134-byte `ABEND-DATA` (code, culprit, reason and message, `CSMSG02Y.cpy:21-29`) with `NOHANDLE` and no `ERASE` (lines 924-928), cancels the handler (lines 930-932) and abends with code `9999` (lines 934-936). Its fallback `'UNEXPECTED ABEND OCCURRED.'` is moved only when `ABEND-MSG` holds low-values (lines 918-920). `ABEND-MSG` starts as spaces (`CSMSG02Y.cpy:28-29`) and nothing sets it, so the message is sent blank; the code and the reason are blank too (the `'0001'` of line 377 belongs to the unreachable `WHEN OTHER` above). A CICS abend has no endpoint counterpart.
- The `RESP` of `SEND MAP` (line 589) and of `RECEIVE MAP` (lines 614-615) is never tested; the one case where that matters is halt candidate `X-COACTVWC-H2`.

## Rules governing this file

- Cardholder Data Redaction (E32): the SSN leaves the service only as `***-**-` followed by its last four digits (COACTVWC-017), and the card number that the cross-reference read moves to the COMMAREA is in no response (COACTVWC-034). This file quotes no card number, SSN or other fixture value; facts about the fixtures are stated as counts.
- Typed Dates and Timestamps: the four displayed dates are typed in `AccountViewResponse` (COACTVWC-014, COACTVWC-019); the request carries the raw account-number text, which the program edits.
- Behaviour constraint: the overwritten prompt (X-COACTVWC-1), the never-true message tests (X-COACTVWC-2), the file error for an account with several cards (X-COACTVWC-4) and the narrowed display fields (X-COACTVWC-5) are expected results, reproduced and never fixed.
- Equivalence failure constraint: the CICS `RESP` and `RESP2` values inside the not-found and file-error texts are `HALTED(H4)` and assert nothing, while the text around them, the status and the field remain assertable rows. What the halt candidates below name gets no parity assertion until the reviewer rules on them.
- Thin Request Handlers: every outcome here is decided by `domain::online::coactvwc` and `api::services::coactvwc`; the handler of endpoint 4 only extracts the path parameter and the `SignedOnUser`, calls the service and maps its outcome.
- R7 — Anomaly handling: anomalies are cited by escalation ID or proposed below as `X-COACTVWC-<n>`, never normalised. R16 — Authority and protected paths: `app/**` is read only.
