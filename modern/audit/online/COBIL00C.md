# COBIL00C — bill payment (CB00)

This is the derive-lane (#2) audit of `COBIL00C` (`app/cbl/COBIL00C.cbl`, 572 lines), the CICS program behind transaction `CB00`, map `COBIL0A` of mapset `COBIL00`, menu option 10 of `COMEN01C`. The replacement serves it as endpoint 15, `POST /api/v1/bill-payments`, which takes `BillPaymentRequest { acct_id, confirm }` and returns `BillPaymentResult` (balance, message, new transaction ID) or `ScreenError { message, field? }`, and as the screen `COBIL00` at route `/bill-payment`. The file comes before `crates/domain/src/online/cobil00c.rs`, `crates/api/src/{services,dto,handlers}/cobil00c.rs`, `crates/api/tests/endpoints_reports_billpay.rs` and `frontend/src/screens/COBIL00.tsx`, and code that consumes it is accepted only once the reviewer marks it `Accepted` in the status table of `modern/audit/README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16).

## Reading the table

- Rule ID: `COBIL00C-<nnn>`, in the order the program runs: entry and keys, the edits of `PROCESS-ENTER-KEY`, the account read, the payment block, the writes, then what the screen renders; COBIL00C-038, the token check that stands for the COMMAREA test of COBIL00C-001, comes last.
- Paragraph: the paragraph whose statements decide the row; Copybook field or PIC: the fields the rule reads or writes, as declared, with the `copybooks.md` row that types them.
- Input condition: the request (`acct_id`, `confirm`) and the stored state it meets. Blank means absent, empty or all spaces, which stands for the COBOL's `SPACES` or `LOW-VALUES`.
- Expected result: the HTTP status and body, the field the screen focuses, and the store effects. `200` returns `BillPaymentResult`; `400`, `404` and `500` return `ScreenError` with the exact literal the program moves to `WS-MESSAGE`. The program's cursor (`ACTIDINL` or `CONFIRML` set to −1) becomes `field` `acct_id` or `confirm`.
- One pseudo-conversational task is one request. The program can send its screen several times in one task, each send erasing the last, so the response is the last screen it sends (COBIL00C-034).
- Layer: `server` rows are observable through endpoint 15, `client` rows send no request, as `README.md` defines them. The map lengths of `ACTIDIN` (11) and `CONFIRM` (1), which the zod schema and the request DTO both enforce, are the `both` rows `COBIL00-013` and `COBIL00-020` of `screens.md`; no edit of this program is repeated by the schema, so every edit row here is `server`.

## Rules governing this file

- Money constraint and financial exactness (o3): every amount comes from an `ARITH-` row, which fixes its receiving PIC and its truncation; the balance travels as the 14-character string of ARITH-019; no row implies floating point.
- Cardholder Data Redaction: endpoint 15 returns no card number. `BillPaymentResult` holds the balance, the message and the transaction ID; the card number the payment writes reaches only `transactions.card_num` (CVTRA05Y-011). This file quotes no fixture card or account value.
- Typed Dates and Timestamps: both timestamps the payment writes are typed `TIMESTAMP(6)` values with layout code `I` (COBIL00C-027, PIC-018, E33).
- Behaviour constraint and R7 — Anomaly handling: the defects audited here are reproduced, E11 included; anomalies and cases with no single result are proposed below the table, never smoothed over.
- Thin Request Handlers: every outcome in the table is decided by `domain::online::cobil00c` and carried out by `api::services::cobil00c`; the handler only extracts, calls the service and maps.
- Bounded Pagination: endpoint 15 returns a single resource and takes no page size.
- R16 — Authority and protected paths: markdown under `modern/audit/` only.
