# COADM01C — admin menu (CA00)

This is the derive-lane (#2) audit of `app/cbl/COADM01C.cbl` (288 lines), the admin menu program of transaction `CA00` and map `COADM01` (`COADM1A`). Its replacement is endpoint 3, `GET /api/v1/menus/admin` [A] → `MenuResponse`: the fixed option table compiled from `COADM02Y` (six options, each with its number, name, display text, program and its admin-only and installed flags) and the program's two option messages (AAP 0.3.4.1). The screen is `modern/frontend/src/screens/COADM01.tsx` at route `/admin`. ENTER and the option checks are served on the screen from the response it already holds, so they send no request. The rows come before `crates/domain/src/online/coadm01c.rs`, `crates/api/src/services/coadm01c.rs`, `crates/api/src/{dto,handlers}/coadm01c.rs`, `crates/api/src/auth/extract.rs` and the tests that bind them, and code that consumes them is accepted only once this file is `Accepted` in the status table of `modern/audit/README.md` (a8, a9). The transfer into this menu is sign-on's, audited in `online/COSGN00C.md` (`COSGN00C-014`, `COSGN00C-015`, `COSGN00C-017`) and not repeated here.

## Reading the table

- Rule ID: `COADM01C-<nnn>`, numbered in program order from `001`; the six option rows follow the table order of `COADM02Y`.
- Paragraph: the COADM01C paragraph that holds the rule; `A → B` names the paragraph `A` performs.
- Input condition: the request, key or entry state that reaches the paragraph. The option entry is the 2-character `OPTION` input (COADM01-025); it is never sent.
- Expected result: for a `server` row, the HTTP status and the content of `MenuResponse`; for a `client` row, what the screen shows and where it goes, with no request. Message literals are given exactly as the program moves them, in single quotes with their spacing. Outcomes are those of the service; how the handler maps them is not part of a row (Thin Request Handlers).
- Layer: `server` rows are observable through endpoint 3; `client` rows send no request. No row is `both`: the option entry reaches no request DTO (COADM01-025), so the option edits run only on the screen, from the table and messages the response carries.
- `HALTED(X-COADM01C-Hn)` marks a row whose COBOL result a halt candidate blocks; no parity value is asserted for it. A row that cites a halt candidate without `HALTED` asserts everything except what the candidate names.

## Rules governing this file

- Identity and Trust (AAP 0.5.1) and the admin gate (AAP 0.3.4.6): the only authority is the `usr_type` claim of the verified token. The `AdminUser` extractor of endpoint 3 is the control; the frontend route guard on `/admin` only hides the screen (`COADM01C-001`). The response is the same for every admin and depends on no request field.
- Bounded Pagination: endpoint 3 returns a single resource, the fixed six-entry table, not a collection. It takes no `page_size`, and no row audits a page-size bound.
- Messages and HTTP status (`README.md`): endpoint 3 answers 200 with the response, 401 without a valid token and 403 for a token whose user type is not `A`. The two option messages travel inside the 200 response and are shown without a request, so no message row carries an error status of its own.
- Cardholder Data Redaction: no card number, SSN, CVV or password passes through this program, and the token carries only the user ID and user type.
- Behaviour constraint and R7 — Anomaly handling: the branches unreachable for the shipped table (`COADM01C-018`, `COADM01C-019`) are recorded as expected results; anomalies are proposed under the candidate headings below, never normalised. R16 — Authority and protected paths: `app/**` is read only, and this file is markdown under `modern/audit/`.
