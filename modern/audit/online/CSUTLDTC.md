# CSUTLDTC audit: date validity through Language Environment `CEEDAYS`

This is the derive-lane (#2) audit of CSUTLDTC, the called subprogram that hands a date and a picture string to the Language Environment service `CEEDAYS` and returns the verdict as an 80-byte text, together with `EDIT-DATE-LE` of the procedure copybook CSUTLDPY, through which COACTUPC calls it, and the working storage of CSUTLDWY that paragraph uses. It supplies the date-validity subset of `modern/crates/domain/src/online/csutldtc.rs` (AAP 0.6.1), the date edits of `modern/crates/api/src/services/{coactupc,cotrn02c,corpt00c}.rs`, and the tests `modern/crates/api/tests/endpoints_accounts.rs`, `endpoints_transactions.rs` and `endpoints_reports_billpay.rs` (g1b). The verdict itself is halt H5: `CEEDAYS` decides which date text is valid, outside the repository, so no row asserts a validity result.

- Language rules the reviewer confirms, from the [Enterprise COBOL for z/OS 6.4 Language Reference](https://publibfp.dhe.ibm.com/epubs/pdf/igy6lr40.pdf): `INITIALIZE` without `REPLACING` sets alphanumeric items to spaces and numeric items to zero, and excludes elementary `FILLER` items and redefining items; an alphanumeric or group `MOVE` left-justifies and truncates on the right; a group containing `OCCURS DEPENDING ON` is as long as the current value of its object; a format-1 `EXIT` is treated as `CONTINUE`, and IBM's extension allows other sentences in its paragraph, which then run; `CALL … USING` passes `BY REFERENCE` unless stated otherwise, so a called program addresses the caller's storage at its own declared lengths; `BINARY` halfwords are stored high-order byte first on z/OS.

## How the rows are proved

- Layer: every row is `server`. CSUTLDTC's outcome is observable only through what endpoints 6, 13 and 14 return (status, message, error field, the accepted date or job deck). No screen checks calendar validity: the zod schemas of `COACTUP`, `COTRN02` and `CORPT00` repeat only the map `LENGTH` and `NUM` attributes (`screens.md`), so no row has a client half. A row's tag goes in the endpoint test of each consumer whose request reaches the cited statements: `endpoints_accounts.rs` for COACTUPC and CSUTLDPY, `endpoints_transactions.rs` for COTRN02C, `endpoints_reports_billpay.rs` for CORPT00C, and all three for the rows of `CSUTLDTC.cbl` itself.
- `HALTED(H5)` rows: the Expected result depends on what `CEEDAYS` returns for a given date and picture: the verdict, the feedback token and the severity and message number taken from it, the `EVALUATE` branch, the `RETURN-CODE` value, the numbers embedded in COACTUPC's message, and which branch of a consumer's test a date takes. No endpoint test can choose that verdict. Each such row still records what the COBOL fixes once the token is known, which is what a source-backed resolution of H5 turns into assertions; until then its tagged tests report the case `BLOCKED` and assert no parity value.
- Rows that cite `halt H5` without the marker fix something that holds for every verdict of the class their Input condition names, such as the fixed text of COACTUPC's message for any non-zero severity. They stay provable; a test reaches them by substituting the date-validity verdict, the one value H5 leaves open.
- Rows with neither are deterministic whatever `CEEDAYS` returns: parameter widths, layouts, the set-up of the call, the flag reset after `EDIT-DATE-LE`, and the consumers' call sites.

## Reading the table

- Rule ID: `CSUTLDTC-<nnn>` in source order: `CSUTLDTC.cbl` 001-018, `CSUTLDPY.cpy` with `CSUTLDWY.cpy` 019-026, then the consumers' call sites, COACTUPC 027, COTRN02C 028-029 and CORPT00C 030-031.
- Program: the program whose statements the row cites. The CSUTLDPY rows name `CSUTLDPY (in COACTUPC)`, its only includer.
- Copybook field or PIC: the working-storage or linkage item with its PIC; none of them is a `copybooks.md` field.
- Positions are 1-based byte positions in the 80-byte result. A literal is quoted exactly as the source moves it; the value a receiver then holds is described with its padding, for example `'Insufficient'` stored as `Insufficient` followed by three spaces. Feedback tokens are quoted as the hexadecimal `VALUE` literals of the 88-levels.
- Short file names resolve as follows: `CSUTLDTC.cbl`, `COACTUPC.cbl`, `COTRN02C.cbl` and `CORPT00C.cbl` in `app/cbl/`; `CSUTLDPY.cpy` and `CSUTLDWY.cpy` in `app/cpy/`.

## Rules governing this file

- Equivalence failure (H5, AAP 0.8.5): no expected validity result is invented. A `HALTED(H5)` row asserts nothing, and every binding over it is reported `BLOCKED`; a reviewer acknowledging H5's analysis does not resolve it.
- Typed Dates and Timestamps: the consumers' date inputs stay raw request text, namely COACTUPC's date parts, COTRN02C's original and processing dates and CORPT00C's start and end date parts, so that the edit messages these rows feed stay reproducible (the raw-edit-input exception of AAP 0.3.4.1). CSUTLDTC is the edit whose acceptance turns that text into a typed `NaiveDate` in `domain::online::csutldtc`; the Lilian day number `CEEDAYS` returns is never read (CSUTLDTC-006) and no typed value is derived from it.
- Thin Request Handlers: every outcome is stated as `domain::online::csutldtc` and the consumers' services own it: the verdict, the message composition and the flags. No row describes a handler.
- R7 — Anomaly handling: oddities are recorded as found. The ones that change behaviour are proposed below as `X-CSUTLDTC-<n>`; the misleading 88-level name `FC-INVALID-DATE`, which changes nothing, is recorded in its row only.
- Cardholder Data Redaction: CSUTLDTC handles no protected value; this file quotes none. Bounded Pagination: the page-size status is not used; the one status stated here is 400.
- R16 — Authority and protected paths: `app/**` is read only.

## Escalation candidates

Proposed under R7 — Anomaly handling. The reviewer folds each candidate into `ESCALATIONS.md` under the next free ID, as its `## Later entries` section describes; until then the rows above cite the candidate names.

- `X-CSUTLDTC-1`
  - Found in: `app/cpy/CSUTLDPY.cpy:291-296`; `app/cpy/CSUTLDWY.cpy:4-37,58-61`; `app/cbl/COACTUPC.cbl:35,151,166,866-868`; `app/cbl/CSUTLDTC.cbl:84-85,105-113`.
  - Anomaly class: declaration-not-followed.
  - Finding: `EDIT-DATE-LE` passes the 8-byte `WS-EDIT-DATE-CCYYMMDD` and the 8-byte `WS-DATE-FORMAT` to parameters CSUTLDTC declares as `PIC X(10)`, and CSUTLDTC takes `LENGTH OF` its own declarations, so every call reads two bytes past each field. Past the picture lie two bytes of the just-initialised result, spaces, so `CEEDAYS` gets `YYYYMMDD` and two spaces (CSUTLDTC-020). Past the date lie the first two bytes of `WS-EDIT-DATE-BINARY`, which the `INITIALIZE` of `WS-MISC-STORAGE` at the start of every task has set to zero and nothing assigns again before the last call, so `CEEDAYS` gets the eight date characters and `X'0000'` (CSUTLDTC-021). COTRN02C and CORPT00C pass 10-byte fields and are not affected.
  - Proposed resolution: both byte sequences are deterministic and recorded as audited. How `CEEDAYS` treats the date string with its two `X'00'` bytes is H5's and is handed to halt candidate `X-CSUTLDTC-H1`, with no parity assertion. The replacement judges the eight date characters alone, which is not claimed as parity for COACTUPC's dates.
- `X-CSUTLDTC-2`
  - Found in: `app/cbl/CSUTLDTC.cbl:25-31,52,107-108,122`.
  - Anomaly class: declaration-not-followed.
  - Finding: after the call, `MOVE WS-DATE-TO-TEST TO WS-DATE` moves the whole 12-byte string, length halfword first, into the 10-byte `WS-DATE`, so the `'TstDate:'` field of the result holds `X'000A'` and the first eight date bytes instead of the date copied there at line 107 (CSUTLDTC-007).
  - Proposed resolution: preserved as audited wherever the 80-byte result is modelled. No consumer reads positions 20-80 (CSUTLDTC-003), so no endpoint exposes the bytes and no endpoint test asserts them.
- `X-CSUTLDTC-3`
  - Found in: `app/cpy/CSUTLDPY.cpy:300-316,323-331`; `app/cbl/COACTUPC.cbl:1482,1494,1507,1538-1543`.
  - Anomaly class: declaration-not-followed.
  - Finding: `EDIT-DATE-LE-EXIT` holds a second sentence after its `EXIT`, `SET WS-EDIT-DATE-IS-VALID TO TRUE`, under the comment "If we got here all edits were cleared". The rejection branch's `GO TO EDIT-DATE-LE-EXIT` lands on it too, so the year, month and day flags that lines 302-304 set not valid are reset to valid before COACTUPC copies them.
