# CORPT00C — transaction report submission (CR00)

This is the derive-lane (#2) audit of `CORPT00C` (`app/cbl/CORPT00C.cbl`, 649 lines), the CICS program behind transaction `CR00`, map `CORPT0A` of mapset `CORPT00`, menu option 9 of `COMEN01C`. It prints transaction reports by submitting the batch job `TRNRPT00`, which runs procedure `TRANREPT`, through the extrapartition transient data queue `JOBS`. The replacement serves it as endpoint 14, `POST /api/v1/reports/transactions`, which takes `ReportRequest { monthly, yearly, custom, start_date, end_date, confirm }` and returns `ReportResult { message, job_deck? }` or `ScreenError { message, field? }`, and as the screen `CORPT00` at route `/reports`. Under the destination decision of AAP 0.3.4.4 the deck the COBOL writes to `JOBS` goes to the local filesystem instead: one generation file `TRNRPT00.G<nnnn>` in `CARDDEMO_INTRDR_DIR` (default `./var/jobs/`), named by `runtime::gdg`. The endpoint does not run the report; running it is the operator's `carddemo-batch tranrept`, as JES ran the submitted job. This file comes before `crates/domain/src/online/corpt00c.rs`, `crates/api/src/{services,dto,handlers}/corpt00c.rs`, `crates/api/tests/endpoints_reports_billpay.rs` and `frontend/src/screens/CORPT00.tsx`, and code that consumes it is accepted only once the reviewer marks it `Accepted` in the status table of `modern/audit/README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16).

## Reading the table

- Rule ID: `CORPT00C-<nnn>`, in the order the program runs: entry and keys, the report selection, the Monthly and Yearly dates, the custom edits, the confirmation, the deck and its write, the submission message, then what the screen renders; CORPT00C-043, the token check that stands for the COMMAREA test of CORPT00C-001, comes last.
- Request: ENTER is the only key endpoint 14 serves, so `ReportRequest` carries no `aid`. Its fields are text: `monthly` (`MONTHLY`, 1), `yearly` (`YEARLY`, 1), `custom` (`CUSTOM`, 1), `start_date` with the parts `month` (`SDTMM`, 2), `day` (`SDTDD`, 2) and `year` (`SDTYYYY`, 4), `end_date` with the parts `month` (`EDTMM`, 2), `day` (`EDTDD`, 2) and `year` (`EDTYYYY`, 4), and `confirm` (`CONFIRM`, 1). The date parts are raw screen input to the program's edits, not typed dates (Typed Dates and Timestamps: the raw-edit-input exception of AAP 0.3.4.1). The server pads each value with spaces to its map length and reads an absent field as empty.
- Input condition: the request and the state that select the rule. Blank means absent, empty or only spaces, which stands for the COBOL's `SPACES OR LOW-VALUES`. "Custom path" means `monthly` and `yearly` blank and `custom` not blank (CORPT00C-007).
- Expected result: the HTTP status and body, the field the screen focuses, and the file written. `200` returns `ReportResult`; `400` and `500` return `ScreenError` with the exact literal the program moves to `WS-MESSAGE`, quoted without the trailing spaces of `WS-MESSAGE PIC X(80)`; `401` comes from the `SignedOnUser` extractor. A `ScreenError`'s `field` names the request field on which the COBOL puts the cursor (`MOVE -1 TO <field>L`), a date part written as its dotted path, for example `start_date.month`. Statuses 403, 404 and 409 are unused, and the page-size rejection of the collection endpoints never applies: endpoint 14 returns a single resource and takes no page size (Bounded Pagination).
- "No deck" means that no file is created in `CARDDEMO_INTRDR_DIR` and `job_deck` is absent.
- Dates that come from the current date use the injected `Clock`; the values given hold under the `FixedClock` instant the row names, and every other time-dependent value is compared by format.
- Layer: `server` rows are observable through endpoint 14 (status, message, field, response values or the deck file), `client` rows send no request, as `README.md` defines them.

## Rules governing this file

- Local-Only Runtime and the destination decision of AAP 0.3.4.4: the deck goes only to the configured local directory; the response carries the message and the generation file's name, never a stream, a path, report content or a card number.
- Typed Dates and Timestamps: the date parts stay raw request text so that the program's edit messages stay reproducible; a custom date becomes a typed `NaiveDate` only when the date edit accepts it (`online/CSUTLDTC.md`), and the Monthly and Yearly dates come from the typed `Clock`. The deck holds each date as its 10-character text.
- Equivalence failure and H5: which custom dates are valid is decided by `CEEDAYS`, so CORPT00C-027 is `HALTED(H5)` and asserts nothing; rows that cite halt H5 without the marker fix only what holds for every verdict.
- Behaviour constraint and R7 — Anomaly handling: the program's oddities are reproduced as expected results, among them the first-error-wins flow, the unreachable year messages, the selection by any non-blank character and the date parts' normalisation; anomalies and cases with no single result are proposed below the table, never smoothed over.
- Thin Request Handlers: every outcome is decided by `domain::online::corpt00c`, and `api::services::corpt00c` writes the deck file through `runtime::gdg`; the handler only extracts, calls the service and maps.
- Cardholder Data Redaction: endpoint 14 handles no card number, SSN, CVV or password, and this file quotes none.
- R16 — Authority and protected paths: markdown under `modern/audit/` only; `app/**` is read in place.

Proposed under R7 — Anomaly handling. The reviewer folds each candidate into `ESCALATIONS.md` under the next free ID, as its `## Later entries` section describes; until then the rows above cite the candidate names.

- `X-CORPT00C-1`
  - Found in: `app/cbl/CORPT00C.cbl:47-49,434-436,480-493,498-499,556-580`.
  - Anomaly class: declaration-not-followed.
  - Finding: `SEND-TRNRPT-SCREEN` ends with `GO TO RETURN-TO-CICS`, so every send ends the task and the program's error-flag tests after a send are dead: `IF NOT ERR-FLG-ON` at line 434 always holds, the loop's `OR ERR-FLG-ON` at line 499 never ends it (a failed write ends the task inside `WIRTE-JOBSUB-TDQ`), and the `MOVE 'Y' TO WS-ERR-FLG` at lines 482 and 491 affects nothing that runs. `SEND-ERASE-NO` is never set, so the send without `ERASE` (lines 571-577) is never taken.
  - Proposed resolution: deterministic dead branches, preserved as not taken. The replacement returns at the first edit that fails, and every response is a whole screen (CORPT00C-006).
- `X-CORPT00C-2`
  - Found in: `app/cbl/CORPT00C.cbl:305-379,381-426`.
  - Anomaly class: declaration-not-followed.
  - Finding: the six parts are converted by `NUMVAL-C` and moved back as unsigned digits (lines 305-327) before the `IS NOT NUMERIC` tests (lines 329-379), so those tests never hold. The two year messages, `Start Date - Not a valid Year...` and `End Date - Not a valid Year...`, are never sent; the month and day tests reduce to `> '12'` and `> '31'`, so `00` passes both; one-digit and space-padded entries are accepted as their zero-padded values. - `X-CORPT00C-3`
