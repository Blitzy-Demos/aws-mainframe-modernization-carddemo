# COPAUS0C — authorization summary (CPVS, endpoint 21)

This is the derive-lane (#2) audit of COPAUS0C, `app/app-authorization-ims-db2-mq/cbl/COPAUS0C.cbl` (1,032 lines), the CICS program of transaction `CPVS`, which sends and receives map `COPAU0A` of mapset `COPAU00`. It shows one account's customer, the account's pending-authorization summary and its pending authorizations five to a page, and transfers to COPAUS1C (`CPVD`) for the one the operator selects. Its replacement is endpoint 21, `GET /api/v1/accounts/{acct_id}/authorizations` with the query parameters `page_key`, `direction` and `page_size`, returning `AuthSummaryResponse`, and the screen `frontend/src/screens/COPAU00.tsx` at route `/authorizations` (AAP 0.3.4.1, 0.3.5). The IMS database `DBPAUTP0` it browses is the root segment `PAUTSUM0` → table `pending_auth_summaries` (primary key `acct_id`) and the child segment `PAUTDTL1` → table `pending_auth_details` (primary key `acct_id`, `auth_date_9c`, `auth_time_9c`), migration `0004_authorizations.sql`.

This file comes before `crates/domain/src/online/copaus0c.rs`, `crates/api/src/services/copaus0c.rs`, the authorization page query in `crates/persistence/queries/`, `crates/api/src/{dto,handlers}/copaus0c.rs`, `crates/api/tests/endpoints_authorizations.rs` and the COPAU00 screen. Code that consumes it is accepted only once the reviewer marks it `Accepted` in the status table of `../README.md` (a8, a9; AAP 0.8.6). Paths under `crates/` and `frontend/` are relative to `modern/`. Every source was read in place at commit `59cc6c2` and none was changed (R16).

## Reading the table

- Rule ID: `COPAUS0C-<nnn>`, in this order: entry and keys (001–004), the ENTER edits and the selection (005–012), the reads and their messages (013–019), the customer block (020–026), the summary block (027–030), the list (031–038), paging (039–050), then the rows that hold for every send and the halted code fields (051–056).
- Paragraph: the COPAUS0C paragraph that holds the rule; `→` names a paragraph it performs.
- Copybook field or PIC: the fields the rule reads or writes, with their PICs and, for a copybook field, its `../copybooks.md` row; map fields are named by their symbolic-map field, `nn` and `nnn` standing for the list row, 01 to 05 and 001 to 005.
- Input condition: the key, the input or the data state. "The state" is the paging state of COPAUS0C-039, which the COBOL keeps in the COMMAREA and the screen keeps in its route state.
- Expected result: what the screen shows or endpoint 21 returns. A message row gives the literal as the program moves it, in COBOL quotes so that leading spaces show, and the status endpoint 21 returns with it: 400 input error, 404 not found, 500 store failure; every other response is 200. The message row of the map holds 78 characters (`ERRMSG LENGTH=78`), so a longer text shows its first 78. Display values travel in `AuthSummaryResponse` as the strings given here, built with the program's pictures; the screen formats nothing.
- Layer: as `../README.md` defines it; `client` rows include what the screen renders and the paging state it keeps.

## Rules governing this file

- Bounded Pagination: endpoint 21 is a collection endpoint. `page_size` defaults to 5, the five list rows of the map, and the screen never sends it. The rejection of a value outside 1 to 100, with the status Bounded Pagination reserves, is not a COBOL rule and has no row here (`crates/api/tests/pagination.rs`). Every "five" below reads as `page_size` when a caller sends one. The page query is served by the primary key of `pending_auth_details` (COPAUS0C-031).
- Cardholder Data Redaction (E32): COPAU00 shows no card number and endpoint 21 returns none (COPAUS0C-055). This file quotes no fixture card number, SSN or account value; the worked values are invented.
- Equivalence failure constraint and H4: H4 lists "the not-found and file-error message rows" of this file among its bindings. Every CICS `RESP` or `RESP2` value and every IMS status code strung into a message is COPAUS0C-056, `HALTED(H4)`, and asserts nothing; the message rows cite halt H4 for the parts it leaves assertable, the fixed text and the account or customer ID they carry. A row whose whole case a halt candidate below names says `HALTED(X-COPAUS0C-Hn)` and asserts nothing; the cases the candidates name get no parity assertion.
- Behaviour constraint and R7 — Anomaly handling: the defects found (X-COPAUS0C-2 to X-COPAUS0C-5) are expected results and are reproduced; anomalies are proposed below as `X-COPAUS0C-<n>` and never normalised.
- Typed Dates and Timestamps: the list's date and time come from `PA-AUTH-ORIG-DATE` and `PA-AUTH-ORIG-TIME` (`X(06)`), which the rule does not cover (CIPAUDTY-003, CIPAUDTY-004), so they travel as the display strings of COPAUS0C-034.
- R16 — Authority and protected paths: `app/**` and `samples/**` are read only; this file is the only one written.

## Escalation candidates

Proposed under R7 — Anomaly handling. The reviewer folds each candidate into `../ESCALATIONS.md` under the next free ID, as its `## Later entries` section describes; until then the rows above cite the candidate names.

- `X-COPAUS0C-1`
  - Found in: `app/app-authorization-ims-db2-mq/cbl/COPAUS0C.cbl:418,445,473-484,506-517,753-755,832-862,882-912,933-963,985-996,1019-1030`.
  - Anomaly class: declaration-not-followed.
  - Finding: a failed read does not end the interaction. `NOTFND` sets no error flag, and every other condition sets `WS-ERR-FLG`, which stops only the list read. Each failure sends the map at once; the remaining reads and field moves still run, and `MAIN-PARA` sends the map again, so the operator sees the last send. Each message is strung into `WS-MESSAGE` from position 1 without clearing it, so a shorter later message leaves the tail of an earlier one in place. With the cross-reference found, a missing account or customer leaves its message on screen with the rest of the block, partly taken from the unread record (X-COPAUS0C-H1), the summary and the first page; a `DUPKEY` leaves the system-error text with the block and the summary and no rows; a failed detail read leaves the rows read before it.
  - Proposed resolution: endpoint 21 stops at the first failed read and returns that read's message alone, 404 for `NOTFND` and 500 otherwise (COPAUS0C-014 to COPAUS0C-019, COPAUS0C-030, COPAUS0C-037, COPAUS0C-038). The block, summary and rows the COBOL still shows after the failure are not returned. Apart from store failures, every such case needs data that no fixture and no in-scope program creates: a cross-reference row without its account or customer, or two cards on one account. The reviewer decides whether endpoint 21 should return them.
- `X-COPAUS0C-2`
  - Found in: `app/app-authorization-ims-db2-mq/cbl/COPAUS0C.cbl:362-379,436-441`.
  - Anomaly class: declaration-not-followed.
  - Finding: `PROCESS-PF7-KEY` subtracts 1 from `CDEMO-CPVS-PAGE-NUM` and repositions at that page's stored first key, but `PROCESS-PAGE-FORWARD` adds 1 at the first row of every page it shows, F7 pages included, and stores the key of the page shown as that page number's first key. After one F7 the page number and the stored key both point at the page displayed, so each further F7 shows it again, and the top-of-page message needs a page number of 1 or less: after an ENTER that showed a page, it appears only until an F8 shows a further one.
  - Proposed resolution: preserved (COPAUS0C-045, COPAUS0C-046): the screen's paging state applies the same arithmetic.
- `X-COPAUS0C-3`
  - Found in: `app/app-authorization-ims-db2-mq/cbl/COPAUS0C.cbl:123-125,183,200,374,418-424,445-452`.
