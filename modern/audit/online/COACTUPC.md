# COACTUPC — account update audit (CAUP)

This is the derive-lane (#2) audit of COACTUPC, the CICS program of transaction `CAUP` (`app/cbl/COACTUPC.cbl`, 4,236 lines), map set `COACTUP`, map `CACTUPA`, route `/accounts/update`. The replacement serves it as endpoint 5, `GET /api/v1/accounts/{acct_id}` → `AccountUpdateView` (the fields and the snapshot), and endpoint 6, `PUT /api/v1/accounts/{acct_id}` with `AccountUpdateRequest { aid, fields, snapshot }` → `AccountUpdateResult`. The file records the account edit, the three reads, every field edit with its message and HTTP status, the change checks, the save and the keys the program serves, together with the `CSLKPCDY` lookups and the date-part edits of `CSUTLDPY` that only COACTUPC performs. It comes before `modern/crates/domain/src/online/coactupc.rs`, the COACTUPC-only subset of `modern/crates/domain/src/online/csutldtc.rs` (AAP 0.6.1), `modern/crates/api/src/services/coactupc.rs`, `modern/crates/api/src/dto/coactupc.rs`, `modern/crates/api/src/handlers/coactupc.rs`, `modern/crates/api/tests/endpoints_accounts.rs` and the COACTUP screen and its tests. Code that consumes it is accepted only once the reviewer marks this file `Accepted` in the status table of `modern/audit/README.md` (a8, a9; AAP 0.8.6). Every source was read in place at commit `59cc6c2` and none was changed (R16).

## Endpoints, states and messages

- Endpoint 5 serves ENTER while no details are shown: the account edit of `1210-EDIT-ACCOUNT` and, when it passes, the reads of `9000-READ-ACCT` (COACTUPC-011, COACTUPC-068). It returns the displayed values, the snapshot and the state.
- Endpoint 6 serves ENTER after a fetch (`aid` ENTER: change check, edits, request for confirmation) and F5 while changes await confirmation (`aid` PF5: the save). Any other `aid` is processed as ENTER (COACTUPC-004).
- F3, F12 and every key pressed on the screen of a finished save send no request (AAP 0.3.4.1; COACTUPC-005, COACTUPC-006, COACTUPC-069).
- State: `ACUP-CHANGE-ACTION` (`COACTUPC.cbl:654-668`), named in the rows by its code: not fetched (spaces or low-values), `S` details shown, `E` changes not OK, `N` changes validated and not confirmed, `C` changes saved, `L` lock failed, `F` rewrite failed. ## Reading the table

- Rule ID: `COACTUPC-<nnn>`, in source order: `0000-MAIN` 001-006, `1100-RECEIVE-MAP` 007-010, `1200-EDIT-MAP-INPUTS` 011-039 (the 24 field edits in their order at 015-038), `1205-COMPARE-OLD-NEW` 040-044, `1210-EDIT-ACCOUNT` 045-047, the generic edits `1215` to `1250` 048-054, `1260-EDIT-US-PHONE-NUM` 055-059, `1265-EDIT-US-SSN` 060-064, `1270` to `1280` 065-067, `2000-DECIDE-ACTION` 068-071, the send paragraphs `3100` to `3390` 072-083, the reads `9000` to `9500` 084-100, `9600-WRITE-PROCESSING` 101-112, `9700-CHECK-CHANGE-IN-REC` 113-116, then the `CSUTLDPY` date paragraphs, copied at line 4232, 117-131.
- Program: `COACTUPC` for every row; the `CSUTLDPY` rows cite the copybook's own lines, which compile as part of COACTUPC.
- Request: `acct_id` is the raw text of the 11-byte `ACCTSID` field (COACTUP-013), right-padded with spaces to 11 and never parsed as a number by the request DTO, so the account edit and its messages are reproduced. Every other field travels as the raw text of its map field, at most the map `LENGTH`, including the date, phone and SSN parts and the amounts (the raw-edit-input exception of AAP 0.3.4.1). The SSN parts are optional (COACTUPC-064).
- A field value written blank means all spaces, low-values (an erased field) or `*` followed only by spaces, which `1100-RECEIVE-MAP` treats alike (COACTUPC-007).
- `field` in a `ScreenError` is the request field bound to the map field the row names (for example `ACSTTUS`, COACTUP-016); the DTO module fixes its JSON name.
- Messages are quoted exactly as the program composes them, without the trailing spaces of `WS-RETURN-MSG`. A composed message is written as `TRIM(<name>)` followed by the literal, where `<name>` is the text moved to `WS-EDIT-VARIABLE-NAME PIC X(25)`; the rows 015-038 spell each result out.
- Statuses follow `modern/audit/README.md`: 400 input error, 404 not found, 409 changed by another user, 500 store failure (lock, rewrite and file errors). This program serves no collection endpoint, so the page-size rejection of Bounded Pagination never occurs. An error response is a `ScreenError`, so the screen sets the state the row names, keeps the last snapshot unless the row says otherwise and shows that state's info message.
- Amounts: an amount shown or returned is the 15-character string of `+ZZZ,ZZZ,ZZZ.99`, as COACTVWC-011 defines it; an amount compared or stored is a `Money<10>` value (`CVACT01Y-003`).

## Rules governing this file

- Cardholder Data Redaction (E32): the SSN leaves the service only as `***-**-` followed by its last four digits, shown in the three SSN fields as `***`, `**` and the four digits (COACTUPC-076); the SSN parts are request input only when the operator re-enters them, and omitted means unchanged (COACTUPC-064, as passwords under E27); the change check at validation and the changed-by-another-user check at save handle the SSN as COACTUPC-044 and COACTUPC-115 state; the card number the cross-reference read returns is in no response (COACTUPC-090). This file quotes no card number, SSN or other fixture value.
- Typed Dates and Timestamps: the four stored dates are returned typed (`NaiveDate`, `null` for a blank field) and the screen splits them into its parts (COACTUPC-074, COACTUPC-075). The date parts of the request stay raw text, the exception of AAP 0.3.4.1, so that the messages of COACTUPC-117 to COACTUPC-130 stay reproducible; the domain's output for an accepted date is a typed date (COACTUPC-131), and a raw text the COBOL would write that is no calendar date is X-COACTUPC-10.
- Equivalence failure constraint: the CICS `RESP` and `RESP2` values in the not-found and file-error texts are `HALTED(H4)`; the date validity of `CEEDAYS` is `HALTED(H5)` (COACTUPC-129); amounts with more than two decimal places are X-ARITH-5. Halted parts assert nothing, and the cases the halt candidates below name get no parity assertion until the reviewer rules on them.
- Behaviour constraint and R7 — Anomaly handling: audited defects are expected results, reproduced and never fixed: the blank that never equals a stored blank (COACTUPC-042), the customer-lock failure reported as committed (COACTUPC-102), the account rewritten without its customer (COACTUPC-107), the group ID written over the ZIP field (COACTUPC-103), the stale snapshot after a 409 (COACTUPC-116), the amounts and ZIP narrowed by the display (COACTUPC-109, COACTUPC-104). Anomalies are proposed below as `X-COACTUPC-<n>`, never normalised.
- Thin Request Handlers: every outcome here is decided by `domain::online::coactupc` and `api::services::coactupc`; the handlers of endpoints 5 and 6 only extract the request and the `SignedOnUser`, call the service and map its outcome.
- R16 — Authority and protected paths: `app/**` is read only.
