# COTRN00C — transaction list (CT00)

Derive-lane (#2) audit of `COTRN00C`, the 699-line CICS program behind transaction `CT00` (map `COTRN0A`, mapset `COTRN00`). It lists the `TRANSACT` file ten records to a page, pages forward and backward by `TRAN-ID`, and hands a selected transaction to COTRN01C. The replacement ports it to `crates/domain/src/online/cotrn00c.rs` and `crates/api/src/services/cotrn00c.rs` and serves it as endpoint 11, `GET /api/v1/transactions`, request `TranListQuery { start_tran_id?, page_key?, direction?, page_size? }`, response `TranListResponse` (10 rows) (AAP 0.3.4.1), shown by `frontend/src/screens/COTRN00.tsx` at `/transactions`. Code that consumes this file is accepted only once it is `Accepted` in the status table of `README.md` (a8, a9; AAP 0.8.6). The COBOL is read in place at commit `59cc6c2` and never changed (R16).

## Sources

- `app/cbl`: `COTRN00C.cbl`, the program; `COTRN01C.cbl` and `COMEN01C.cbl` for the COMMAREA they pass and the key that transfers control.
- `app/cpy`: `CVTRA05Y.cpy` (`TRAN-RECORD`), `COCOM01Y.cpy` (`CARDDEMO-COMMAREA`, which `COTRN00C.cbl:62-70` extends with `CDEMO-CT00-INFO`), `CSDAT01Y.cpy` (`WS-TIMESTAMP`, `WS-CURDATE-MM-DD-YY`), `CSMSG01Y.cpy` (`CCDA-MSG-INVALID-KEY`), `COTTL01Y.cpy` (titles).
- `app/bms`: `COTRN00.bms`; `app/cpy-bms`: `COTRN00.CPY`, whose `COTRN0AO` redefines `COTRN0AI`, so a value moved to a field's `I` name is the value sent.
- IBM CICS TS documentation, for the browse behaviour the program relies on: `STARTBR` without `EQUAL` or `GTEQ` defaults to `GTEQ` and returns `NOTFND` (RESP2 80) when no key is greater than or equal to `RIDFLD`, an empty file included; `READPREV` issued right after a `STARTBR` on an existing key returns that key's record; `READNEXT` and `READPREV` with no active browse return `INVREQ` (RESP2 34 and 41); `ENDBR` with no active browse raises `INVREQ` (RESP2 35), whose default action abends the task with `AEIP`. BMS pads a short entry in a field without `NUM` with blanks (`JUSTIFY` default `(LEFT,BLANK)`).
- `copybooks.md` for the record fields (CVTRA05Y-001, CVTRA05Y-005, CVTRA05Y-006, CVTRA05Y-012; PIC-017 to PIC-021) and `screens.md` for the map fields and keys (COTRN00-001 to COTRN00-099).

## Reading the table

- Tasks and sends: every key the operator presses runs one task. `MAIN-PARA` restores the COMMAREA, dispatches the AID and ends with `RETURN TRANSID('CT00')` and the COMMAREA, except where an `XCTL` leaves the program. A path can send the map more than once; the operator sees the last send, so each Expected result states the final screen. A send without `ERASE` (`SEND-ERASE-NO`) redisplays what the screen showed, with the new message.
- State: `CDEMO-CT00-TRNID-FIRST` and `CDEMO-CT00-TRNID-LAST` (`X(16)`), `CDEMO-CT00-PAGE-NUM` (`9(08)`) and `CDEMO-CT00-NEXT-PAGE-FLG` (`X(01)`) carry the paging from task to task; the rows call them the first key, the last key, the page number and the next-page flag. In the replacement the response returns them and the screen echoes them with its next request. They grant nothing, because every request re-reads `transactions`; X-COTRN00C-1 states what the request has to carry. `CDEMO-CT00-TRN-SEL-FLG` and `CDEMO-CT00-TRN-SELECTED` only hand the selection to COTRN01C.
- Keys: ENTER, PF3, PF7 and PF8 are the AIDs the program serves. A first entry is a task that starts with `CDEMO-PGM-CONTEXT` 0, after an `XCTL` into the program: the menu's option, or COTRN01C's F3 or F5.
- Rows: row 1 is screen line 10 and row 10 is screen line 19. A blank row holds spaces in `TRNIDnnI`, `TDATEnnI`, `TDESCnnI` and `TAMTnnnI`.
- Status: 400 with `ScreenError { message, field }` for an input error, 500 with `ScreenError { message }` for a failed read, and 200 for every page read and every boundary message, with the program's message in the response when one was moved. 422 is no COBOL outcome (Bounded Pagination, below).
- Halts and candidates: a row whose value a halt candidate names says `Not asserted` and gets no parity assertion until the reviewer folds the candidate in or rejects it. A row that cites `halt H4` stays provable apart from the CICS codes it names.

## Rules governing this file

- Bounded Pagination: endpoint 11 is a collection endpoint. Its `page_size` defaults to the screen's 10 rows, which every row below assumes, and the screen never sends it. A `page_size` from 1 to 100 replaces 10 as the rows of a page, the row that sets the last key and the position of the read-ahead record. A value outside that range is rejected with 422 and a `ScreenError`: a Bounded Pagination rule proved by `crates/api/tests/pagination.rs`, not a COBOL row. The page query, a file in `crates/persistence/queries/`, is served by the `transactions` primary key on `tran_id`, the KSDS key the program browses (CVTRA05Y-001), read ascending for a forward page and descending for a backward one.
- Typed Dates and Timestamps: each list row carries `TRAN-ORIG-TS` as the typed `date-time` value `orig_ts` and, beside it, the eight-character display date `MM/DD/YY` that `POPULATE-TRAN-DATA` builds (COTRN00C-029). The display date is a screen picture (`WS-TRAN-DATE PIC X(08)`), not the timestamp field; the domain rule computes it from the typed value, and the screen shows it without formatting the timestamp itself.
- Cardholder Data Redaction: the list shows no card number. `POPULATE-TRAN-DATA` moves only `TRAN-ID`, the date, `TRAN-DESC` and `TRAN-AMT`, so `TranListResponse` carries no card number in any form (COTRN00C-034). This file quotes no fixture transaction ID and no card number.
- Money: the amount travels as the 12-character string that `WS-TRAN-AMT PIC +99999999.99` produces (COTRN00C-032), so the screen does no numeric formatting.
- R7 — Anomaly handling and the Behaviour constraint: the program's paging quirks are expected results: the first selector wins, `s` selects like `S`, PF7 at the top sets the next-page flag, keys outlive their pages, a rejected search resets the page number, and COTRN01C's F5 skips the lowest record. Each is also proposed under `## Escalation candidates`, and each path without a single result under `## Halt candidates`.
- R16 — Authority and protected paths: this audit writes only this file.

## How the rows are proved

- `server` rows: `crates/api/tests/endpoints_transactions.rs`, against a migrated database holding transactions (posted by `carddemo-batch posttran` or inserted by the test) with the injected `FixedClock`; each test carries `// audit: COTRN00C-nnn`. The lookup-error row uses a store double whose page read fails.
- `client` rows: `frontend/src/screens/COTRN00.test.tsx` (selection, invalid key, message precedence, page number, search field, selectors, header), `frontend/src/lib/pfkeys.test.ts` (key bindings) and `frontend/e2e/nav.spec.ts` (the transfers: the menu option to `/transactions`, `S` to `/transactions/view`, F3 to `/menu`).
- No row is `both`. The map gives the search field no `NUM` attribute and the selectors are never sent (`screens.md` COTRN00-015 and COTRN00-027), so no zod schema repeats an edit this file audits; the 16-byte length of `start_tran_id` is COTRN00-015.

## Escalation candidates

- `X-COTRN00C-1`: the state and the key the endpoint has to receive.
  - Found in: `app/cbl/COTRN00C.cbl:62-70,111,138-141,224,236-245,259-267,285-287,305-319,339,359-369`.
  - Anomaly class: request-vs-repository.
  - Finding: The program decides every page from the COMMAREA state and the AID. PF8 browses from the last key and PF7 from the first key, each kept from earlier tasks when its row is not filled (X-COTRN00C-4); PF7 tests the page number and PF8 the next-page flag; ENTER resets the page number and reads without a skip, PF8 continues it with a skip, and a first entry skips unless it arrived by ENTER, PF3 or PF7 (X-COTRN00C-2). `TranListQuery { start_tran_id?, page_key?, direction?, page_size? }` (AAP 0.3.4.1) carries one key and a direction, so it cannot carry both keys, the page number, the next-page flag or the key, and COTRN00C-004 and COTRN00C-013 to COTRN00C-027 could not be reproduced from it.
  - Proposed resolution: As endpoint 25 does with `TranTypeListState`, `TranListResponse` returns the state (first key, last key, page number, next-page flag), and the screen echoes it unchanged in `TranListQuery` together with the key it sends (`ENTER`, `PF7`, `PF8`, or, on a first entry, the key of the transfer that brought the screen up). After a 400 or 500 the state is the echoed one, with page number 0 when the key was ENTER and next-page flag `Y` when it was PF7 (COTRN00C-013, COTRN00C-027); the error body carries it, or the screen applies that one rule. The state grants nothing: every request re-reads `transactions`. `page_key` and `direction` become the carriers of the browse key and the key sent, or give way to the state fields; the choice belongs to the API.
- `X-COTRN00C-2`: a return by COTRN01C's F5 skips the lowest transaction.
  - Found in: `app/cbl/COTRN00C.cbl:112-116,285-287`; `app/cbl/COTRN01C.cbl:125-127,197-208`.
  - Anomaly class: declaration-not-followed.
  - Finding: The forward page skips one record unless `EIBAID` is ENTER, PF7 or PF3, a test made for PF8. On a first entry `EIBAID` is the key that caused the transfer: ENTER from the menu and PF3 from COTRN01C's F3 read from the lowest record, but COTRN01C's F5 (PF5) also skips, so the list it returns to never shows the lowest transaction, and a table of one transaction shows a blank page numbered 0.
  - Proposed resolution: Preserved (COTRN00C-004): COTRN01's F5 navigation passes its key, and the service skips the first record for any key other than ENTER, PF3 and PF7.
- `X-COTRN00C-3`: PF7 at the top sets the next-page flag.
  - Found in: `app/cbl/COTRN00C.cbl:242,245-252,267-268`.
  - Anomaly class: declaration-not-followed.
  - Finding: `SET NEXT-PAGE-YES` runs before the page test, so `You are already at the top of the page...` leaves the flag `Y` even when the page has no successor. A following PF8 then pages forward from the last key: a blank page with `You have reached the bottom of the page...` when the last key is set (COTRN00C-019), or the `ENDBR` abend when it is blank (COTRN00C-020, X-COTRN00C-H1).
  - Proposed resolution: Preserved.
- `X-COTRN00C-4`: keys outlive their pages.
  - Found in: `app/cbl/COTRN00C.cbl:390-393,437-439`; `app/cbl/COMEN01C.cbl:50`; `app/cbl/COTRN01C.cbl:53-61`.
  - Anomaly class: declaration-not-followed.
  - Finding: Only row 1 sets the first key and only row 10 the last key. A forward page of fewer than ten rows keeps the last key of an earlier page, which after a round trip through COTRN01 can come from an earlier visit (from the menu it is spaces), and a backward page that ends early keeps the old first key (COTRN00C-018, COTRN00C-026). The next PF8 or PF7 browses from those keys.
  - Proposed resolution: Preserved: the state is returned unchanged wherever the COBOL leaves it unchanged.
- `X-COTRN00C-5`: a rejected search resets the page number.
  - Found in: `app/cbl/COTRN00C.cbl:209-225,324`.
  - Anomaly class: declaration-not-followed.
  - Finding: After `Tran ID must be Numeric ...` the program still sets the page number to 0 at line 224 but does not move it to the screen, so the screen shows the old number while the state holds 0. A following PF7 answers `You are already at the top of the page...`, and a PF8 continues from the last key as page 1.
  - Proposed resolution: Preserved (COTRN00C-013, COTRN00C-036).
- `X-COTRN00C-6`: the amount picture is one integer digit narrower than the amount.
  - Found in: `app/cbl/COTRN00C.cbl:56,383`; `app/cpy/CVTRA05Y.cpy:10`.
  - Anomaly class: declaration-not-followed.
  - Finding: `WS-TRAN-AMT PIC +99999999.99` has eight integer positions for the nine of `TRAN-AMT PIC S9(09)V99`, so the `MOVE` drops the high-order digit of an amount of 100,000,000.00 or more in magnitude. - `X-COTRN00C-7`: a read that fails inside the browse.

  - Anomaly class: request-vs-repository.
  - Finding: A `READNEXT` or `READPREV` that fails after some rows were read leaves those rows on the screen, counts a forward page that read at least one row, ends the browse and resends the map with `Unable to lookup transaction...`. The replacement reads a page with one query, which returns the whole page or fails, so no read can fail between rows.
  - Proposed resolution: Every failed page query is treated as a failed `STARTBR` (COTRN00C-027): 500 with the message and no rows, the displayed rows kept, the state as COTRN00C-027 states. The partial page is not reproduced.

## Halt candidates

- `X-COTRN00C-H1`, proposed to join H4 (an outcome CICS defines, with no PostgreSQL or HTTP counterpart).
  - Path: `app/cbl/COTRN00C.cbl:259-260,279-287,305-322,591-611,646-652,692-696` (COTRN00C-020). A `STARTBR` that returns `NOTFND` sets end-of-file but not the error flag, so `PROCESS-PAGE-FORWARD` goes on: on PF8 its skip `READNEXT` runs with no active browse (`INVREQ`, RESP2 34, which its `RESP` turns into `Unable to lookup transaction...`), and in every case it reaches `ENDBR`, which has no `RESP` option. Reached by ENTER or a first entry when no `TRAN-ID` is at or above the browse key (a search value above the highest ID, or an empty table), and by PF8 with a blank last key (browse key high-values), which X-COTRN00C-3 makes reachable.
  - Why no single result: `ENDBR` with no active browse raises `INVREQ` (RESP2 35), whose default action abends the task with `AEIP` (IBM CICS TS documentation, `ENDBR`). The terminal receives CICS's abend message `DFHAC2206` after the map the program sent, and the task ends without `RETURN TRANSID`, so the state is not saved. The screen the operator is left with and what the next key does are defined by CICS, not by the COBOL, and an HTTP response has no counterpart for either.
  - Bindings blocked: g1b: COTRN00C-020 of `modern/audit/online/COTRN00C.md`. NAV is not affected: `scripts/e2e.sh` posts the fixture transactions before the suite opens the list.
  - Escalation: none yet; the reviewer adds one to `ESCALATIONS.md` when folding the candidate in.
  - Candidate resolution: user descoping, or a mapping of the abend to an HTTP outcome (for example 500 with the last message sent) that the user accepts, backed by the IBM `ENDBR` and `DFHAC2206` documentation.
- `X-COTRN00C-H2`, proposed to join H2 (a WORKING-STORAGE value with no `VALUE` that nothing has assigned).
  - Path: `app/cbl/COTRN00C.cbl:78,206-225,279-283,591-619`; `app/cpy/CVTRA05Y.cpy:4-5` (COTRN00C-013). `TRAN-RECORD` is copied into WORKING-STORAGE with no `VALUE`. For a search value that is neither blank nor numeric nothing assigns `TRAN-ID`, and `PROCESS-PAGE-FORWARD` issues `STARTBR` at that key before it tests the error flag.
  - Why no single result: The key is whatever storage the task started with, which no source in the repository sets (Language Environment's `STORAGE` runtime option defaults to no initialisation, and Enterprise COBOL leaves an item without `VALUE` undefined). `NORMAL` leaves `Tran ID must be Numeric ...` as the final message; `NOTFND` (no `TRAN-ID` at or above that key, an empty table included) replaces it with `You are at the top of the page...`; any other response replaces it with `Unable to lookup transaction...`. No `ENDBR` follows, because the error flag skips it.
  - Bindings blocked: g1b: the final message and status of COTRN00C-013. The page-number reset, the absence of a page read and the kept screen stay assertable.
  - Escalation: none yet; the reviewer adds one to `ESCALATIONS.md` when folding the candidate in.
  - Candidate resolution: as H2, Language Environment storage-initialisation documentation for the deployed runtime options. Under `STORAGE(00,...)` the key is low-values, and the message stays `Tran ID must be Numeric ...` whenever the table holds a transaction.
- `X-COTRN00C-H3`, proposed as a new halt (results the compiler's code generation defines).
  - Path: `app/cbl/COTRN00C.cbl:56,383-388`; `app/cpy/CSDAT01Y.cpy:31-35,43-47` (COTRN00C-030, COTRN00C-033).
  - Why no single result: (1) For a blank `TRAN-ORIG-TS`, `POPULATE-TRAN-DATA` moves spaces into the unsigned `PIC 9(02)` fields `WS-CURDATE-MM`, `WS-CURDATE-DD` and `WS-CURDATE-YY`, from a reference-modified alphanumeric item and from two `PIC 9(02)` fields holding non-numeric data. Whether the zone of the last byte is forced to a digit is code generation, so the source does not fix the displayed date. (2) For a negative `TRAN-AMT` whose eight low-order integer digits and two decimals are all zero, the edited sign depends on whether the compiled `MOVE` tests the sign of the full value or of the truncated, all-zero one.
  - Bindings blocked: g1b: COTRN00C-030 and COTRN00C-033. Neither case arises from fixture-derived data: every in-scope writer of `TRAN-ORIG-TS` writes a date (`copybooks.md` CVTRA05Y-012), and a negative amount of that size comes only from a POSTTRAN input other than the fixture.
  - Escalation: none yet; the reviewer adds one to `ESCALATIONS.md` when folding the candidate in.
  - Candidate resolution: IBM Enterprise COBOL documentation of a numeric `MOVE` of non-numeric data and of fixed sign insertion after truncation, for the deployed compiler options, or user descoping.
